# BlockAds 1.0.2 — changes and verification

This is the historical 1.0.2 baseline. The later authorized 1.0.3 addition of dated,
exact-host threat rules and its updated checks are documented in
[THREAT-ADDITIONS-2026-10-18.md](THREAT-ADDITIONS-2026-10-18.md).

The original review findings are fixed in the user-selected reviewed-catalog version. uBlock Origin Lite was a design reference only; no uBOL code or lists were copied.

## Runtime fixes

- Replaced the invalid `||*` URL-filter anchors that prevented Chrome from loading the original extension. Kept the six ad path patterns within their original third-party/resource scope.
- Canonicalized custom hostnames, including Unicode to punycode, and rejected malformed input before saving. Invalid old saved entries are preserved separately and shown as inactive.
- Serialized settings mutations so simultaneous switches and domain additions do not lose one another's changes.
- Verify actual browser rules before reporting success. Browser or storage failures return a visible error, attempt rollback and allow a later retry. Failed input stays in the popup.
- Account for Firefox returning `null` for absent optional DNR fields during rule verification.
- Make inherited site exceptions explicit. Resuming a child site removes the parent exceptions that still permit it, with the affected parent scope displayed.
- Apply the top page's cosmetic exception inside cross-origin frames using browser-provided sender metadata. Ignore stale asynchronous cosmetic-state responses.
- Preserve intentional pause across startup/update handling. Manifest rulesets start disabled so saved preferences can be reconciled before enabling them.
- Improve error, disabled, long-domain and keyboard-focus presentation while preserving the existing design.

## Reviewed-catalog integration

Preserved the coordinated catalog work selected by the user: 94 ad domains plus six browser-only patterns, 80 tracker domains, and 73 unverified observation records. The unverified records are not enabled as a malware layer. The old malware switch is retired without discarding valid ad/tracker settings. Shared-CDN blanket blocking, broad country-code TLD rules, placeholder domains and unsupported miner filename heuristics are excluded.

The catalog/build/export files are maintained with the CyberAssist integration chat. Builds are offline, validate a closed bounded schema, retain exact/subdomain browser scope, serialize publication, and restore prior files after a write failure. Legacy online/CSV import switches fail before downloading or replacing anything. Removed the unused online helper code and the empty cache created during the earlier implementation of this task.

README now describes the actual coverage and permissions and removes the claim of immunity to supply-chain attacks. Structural review of a list does not establish current reputation or freshness.

Browser tests load an unchanged copy of the extension. DNR matching uses synthetic request descriptions and does not resolve or connect to listed domains. Actual request blocking uses a loopback fixture. A local deny proxy rejects non-loopback HTTP(S) traffic without forwarding or resolving destinations, speculative DNS is disabled, and a reserved-name canary confirms proxy enforcement. Test profiles and loopback servers are disposable; personal profiles and host network settings were not changed. All browser processes started by these tests were closed.

The browser checks cover rule acceptance/matching, simultaneous changes, IDN matching, rejected input, popup feedback, inherited exceptions, actual local request blocking, live cosmetic switches, cross-origin frames, global pause/resume, and reopening the popup. Injected failure paths and startup/update event persistence are exercised in the unit harness; they are not presented as full signed-install/browser-restart proof.

Evidence is saved in [verification/2026-10-18/chrome.json](https://github.com/JasXTD/Module-Engine/blob/5206c62e0f7aeb5b4793c7fbd0719610b06db7a5/verification/2026-10-18/chrome.json) and [firefox.json](https://github.com/JasXTD/Module-Engine/blob/5206c62e0f7aeb5b4793c7fbd0719610b06db7a5/verification/2026-10-18/firefox.json), with popup PNGs alongside them. ## Remaining limits

- Edge's installed launcher and versioned executable exited before an isolated test profile started. Edge runtime behavior remains unverified.
- No listed site, malware payload or online feed was accessed. No current malware-reputation claims were verified, and no confirmed-malware blocking feed is enabled.
- Firefox was tested as a temporary add-on; permanent signed installation and full browser restart behavior were not tested.
- These are bounded regression and integration checks, not proof that every website will remain compatible or every ad/threat will be blocked.
