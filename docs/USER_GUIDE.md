# Module Engine user guide

For installation, see the [project README](../README.md#getting-started). This guide covers the current controls, userscript subset, filtering behavior and permissions.

## Modules and userscripts

Use **New script** to start from an explicit example site scope, or **Import** to read a local UTF-8 `.user.js` file. Review the code, sites, timing and APIs in the editor. **Save** stores a script turned off, without running it; after review, turn on **Run this script** beside its name, then reload a matching page. Saving an edit pauses that script again. Duplicate name/namespace identities and stale saves from another editor are rejected. Drafts are preserved when another window changes the library; **Discard draft** explicitly loads the latest saved source.

**Export** saves the current editor text, including an unsaved draft, as a local `.user.js` file; dependency caches and GM values are not included. **Delete** removes the saved source, cached dependencies and GM values after confirmation. Disabling a script or the module unregisters future runs, revokes live API access and cancels pending network requests. It cannot undo arbitrary JavaScript already executed on an open page; reload that page. Re-enabling requires a fresh page load for that script's GM access.

This is an original, focused userscript manager inspired by tools such as [Violentmonkey](https://github.com/violentmonkey/violentmonkey), with a documented compatibility subset:

| Feature | Supported behavior |
| --- | --- |
| Installation and updates | Direct URL installation, manual checks against the approved source URL, read-only current/proposed code and access review, explicit approval and preserved GM values. Applied scripts start paused. |
| Metadata | `@name`, `@namespace`, `@version`, `@description`, `@tag`, HTTP(S) `@match` / `@exclude-match`, URL glob `@include` / `@exclude`, `@run-at`, `@noframes`, `@require`, `@resource`, `@connect` |
| Editor and organization | Syntax highlighting, line numbers, inline syntax errors with **Go to error**, author/local tags, search/filter and configurable start order. |
| Scope | At least one explicit `@match` or `@include`; up to 64 entries per rule type. Either inclusion type can match, and either exclusion type vetoes it. `@match` supports exact hosts, subdomain wildcards and case-sensitive paths. URL globs are case-insensitive and match the full URL, including query/fragment, with `*` as the wildcard and `?` literal. `<all_urls>` means HTTP(S) pages. Browser-restricted pages remain unavailable. |
| Timing and frames | `document-start`, `document-body`, `document-end` (default), `document-idle`; matching frames by default, top frame only with `@noframes`. Legacy value reads and value listeners wait for stored values before running, so document-start can be delayed for those scripts. |
| Execution | A separate native `USER_SCRIPT` world for each script, within the browser's world limit. Chrome/Edge allow **10 isolated worlds per document**; avoid enabling more than 10 scripts whose scopes overlap on one page. `@inject-into content` / `auto` use isolation; `@inject-into page` uses the page world and requires `@grant none`. The default remains isolated even with `@grant none`. |
| Helpers | `GM.info` / `GM_info` identifies Module Engine and exposes `script.grant` (also `grants`), script metadata, UUID, source and actual injection context. `GM.addStyle` / `GM_addStyle` returns the style element with a one-use `.then()` callback. |
| Elements | `GM_addElement` / `GM.addElement` accepts `(tag, attributes?)` or `(parent, tag, attributes?)`. Returns a real DOM element synchronously, with a one-use `.then()` callback. Supports explicit element and shadow-root parents; browser CSP still applies. |
| Tabs | `GM_openInTab` / `GM.openInTab` returns a synchronous handle with `close()`, `closed` and `onclose`. Supports HTTP(S) destinations, background/foreground, adjacent insertion and pinning; see limits below. |
| Clipboard | `GM_setClipboard(data, type?)` writes asynchronously and returns void; `GM.setClipboard` returns a completion promise. Text and HTML only; no reading. Requires optional helper access. |
| Notifications | `GM_notification` / `GM.notification` returns an immediate handle with promise-returning `remove()`. Supports text/options, click and close callbacks. Requires optional helper access. |
| Downloads | `GM_download` returns an abort control with callbacks; `GM.download` returns an abortable promise. Bounded HTTP(S) downloads save through the browser and respect `@connect`. Requires optional helper access. |
| Local values | Synchronous `GM_getValue`, `GM_listValues`, `GM_getValues`; legacy `GM_setValue`, `GM_deleteValue`, `GM_setValues`, `GM_deleteValues` return void and persist asynchronously. All seven corresponding `GM.name` methods return promises. `getValues` accepts an array of keys, an object of defaults, or no argument for all values. Stored values must be JSON-compatible; 256 nonempty string keys and 64 KiB per script. |
| Value listeners | `GM_addValueChangeListener(key, callback)` / `GM_removeValueChangeListener(id)` and `GM.addValueChangeListener` / `GM.removeValueChangeListener`. Callbacks receive `(key, oldValue, newValue, remote)`; creation/deletion uses `undefined`, and `remote` identifies another script instance. Unchanged values do not notify. Up to 256 listeners per instance. |
| Menus | `GM_registerMenuCommand` / `GM_unregisterMenuCommand` and `GM.registerMenuCommand` / `GM.unregisterMenuCommand`. Commands appear in the extension popup for their page tab. Register returns an ID synchronously; the same ID updates a command. Optional `id`, `title`, `accessKey`, `autoClose` (default true), `icon`, or a legacy access-key string. Icons accept inline base64 PNG/JPEG/GIF/WebP up to 32 KiB; other URLs are ignored without fetching. Up to 32 commands per instance. Captions are literal text. |
| Dependencies | Explicit preparation of up to 8 ordered `@require` libraries and 16 uniquely named `@resource` files; 256 KiB each and 1 MiB combined per script. See preparation below. |
| Resources | Synchronous `GM_getResourceText(name)` / `GM_getResourceURL(name)`; promise-returning `GM.getResourceText(name)` / `GM.getResourceUrl(name)` (`GM.getResourceURL` also accepted). Text is decoded as UTF-8; URLs are cached Blob URLs, revoked on final document unload and retained across back/forward cache suspension. Unknown names throw/reject. |
| HTTP | `GM_xmlhttpRequest(details)` with callbacks and `.abort()`, and abortable promise `GM.xmlHttpRequest(details)` (`GM.xmlhttpRequest` also accepted). Supported options and bounds are below. |
| Library limits | 32 scripts, 128 KiB source per script, 1 MiB source overall, 3 MiB total library storage |
| Unsupported | Regex URL rules, `.tld` expansion, extended Violentmonkey `@match` syntax, `@grant unsafeWindow` and unsupported directives/grants are rejected. Icon/update/download URLs remain informational with a visible explanation. Page-world privileged APIs, top-level await, arbitrary non-JSON storage, automatic updates, ZIP backups and cloud sync are unavailable. |

The editor checks syntax and metadata without running the source. Runtime errors still appear in the matching page's developer console. This does not claim full Violentmonkey compatibility or require a localhost server.

Request each helper with its exact `@grant` name. Legacy reads use a hydrated private cache, not a promise disguised as a synchronous API. Legacy writes update that cache immediately, then save in order. A failed write rolls the cache back and logs the failure; use the modern promise-returning methods when the script needs confirmation of persistence. Native value requests retain limits of 8 per browser tab, 16 per script and 64 overall; each document queues at most 64 writes. Up to 64 initial cache connections can wait separately without consuming those value-request slots; manager controls still take priority. Concurrent tabs can overwrite the same key: read/increment/write is not an atomic counter.

To use a script command, open Module Engine on its matching page and choose a button under **Script commands for this page**. **Refresh commands** updates a popup that was already open. Frame commands identify their frame. A callback receives a synthetic click event with modifier keys; browser user activation is not transferred into the script. Editing, disabling, deleting or revoking browser access removes live menus and their capabilities. Page unload disconnects them. A native worker restart reconnects an open document without rerunning its source; after three failed reconnects, reload the page. Existing code and values it already read cannot be taken back.

Menu publication has separate capacity of one pending update per native connection and 64 overall. Updates made while a publication is pending combine into the latest menu state. This leaves ordinary GM value capacity available, and manager controls still take priority.

The 32-script library limit is separate from [Chromium's per-document world limit](https://chromium.googlesource.com/chromium/src/%2B/acf25b09e42fe24738a78dee49f68e51fc6ef867%5E). Chromium can fall back to its default shared world after 10 isolated worlds. Module Engine leaves messaging disabled there, and privileged scripts stop with a console error instead of receiving GM access. Keep overlapping isolated scripts within the limit, including scripts with no privileged grants. Native include-glob prefilters are broader than the exact case-insensitive wrapper: they can consume a world on nearby paths even when the wrapper refuses execution. The manager displays a reminder when more than 10 isolated scripts are enabled across the library.

### Editing and organizing scripts

The source editor highlights JavaScript and metadata, displays line numbers and marks syntax errors. Choose **Go to error** to focus the reported character. It checks the strict script wrapper, so top-level `return` is allowed but top-level `await` is not. It is a syntax check, not a runtime or security audit. Highlighting stops after 20,000 tokens; remaining text stays plain. If parsing exceeds two seconds or the worker fails, the editor retains the source and falls back to plain text.

Use repeated `@tag` metadata for author tags, or enter comma-separated **Your tags** and choose **Save tags**. Each set supports 16 unique tags of 1–64 characters without commas or control characters. Local tags survive source edits and approved updates; they do not alter exported source or `GM_info.script.tags`. Search includes script names, sites and both tag sets; the tag selector filters the library. Saving tags alone keeps the script enabled. Saving source and tag edits together pauses it as usual.

Select a saved script and use **Earlier** or **Later** to change its start order. This applies on the next page load within each `@run-at` phase; different phases still follow their normal timing. Disabled scripts retain their positions. Saved-value hydration and asynchronous work may finish later, so use explicit coordination when one script depends on another's completed work. Tags and ordering are local library settings, not part of a single-file source export.

### Installing and updating scripts

1. Open **Modules & scripts → Install from URL** and paste a direct userscript source URL, usually ending in `.user.js`. Choose **Fetch for review**. A website's HTML file-view page is not a source URL.
2. Review the read-only code, sites, excluded sites, APIs, network scope, timing, frames, execution world and dependencies. Changed settings are marked beside the current values. Fetching does not save, enable or execute anything.
3. Choose **Install script**. The script is saved paused. Prepare and review any dependencies, allow the relevant browser access, then enable **Run this script** and reload a matching page.
4. To update, select the saved script and choose **Check for updates** under **Source & updates**. Review the current and proposed code, then choose **Apply update**. Approval uses exactly the bytes shown, without fetching a different version. The script's ID and latest saved GM values are retained; its source is replaced and it is paused again. Reload pages after enabling it.

Only the URL you explicitly approved is checked. `@updateURL` and `@downloadURL` stay informational and cannot switch the update destination. Checks are manual: no polling, startup downloads or automatic replacement. Clicking a `.user.js` link is not intercepted. For an existing local script, use **Install from URL** with the same `@name` and `@namespace`; the review shows a replacement and links that URL while retaining values. Updates cannot change this identity. Local source edits are shown as the current source and will be replaced only if you approve. Saving a local edit retains its source URL.

Source downloads require HTTPS, except HTTP on `localhost`, `127.0.0.1` or `[::1]` for development. Credentials, URL fragments and redirects are rejected; cookies and referrers are omitted. Use the final direct URL if a host redirects. Limits are 128 KiB of valid UTF-8 source, 30 seconds and four concurrent source downloads. Unsupported metadata, HTML and failed HTTP responses are rejected. **Cancel download** restores the manager immediately. A stale review cannot overwrite a later edit or deletion, and failed commits attempt verified storage/native-registration rollback.

Version comparison uses dotted numeric parts with optional letter suffixes ignored, following the documented [Violentmonkey version convention](https://violentmonkey.github.io/api/metadata-block/#version). Missing or other version formats are explicitly shown as incomparable. Identical source has no update action; changed source with the same version is clearly labeled for review. Numerically older versions cannot be applied through this flow. Updates preserve cached dependencies when their declarations match; changed dependencies require preparation before enabling. Source URLs stay in the local library; single-file **Export** exports source only.

### Clipboard, notifications and downloads

Request the exact API spelling with `@grant`. In **Modules & scripts**, select the script, review its source and choose **Allow helper access**, then accept the browser prompt. These browser permissions are shared by the extension, but each script still needs its own exact grants and a valid native connection. They are optional; the blocker does not need them. The manager displays download destinations from `@connect`, just as it does for HTTP requests.

`GM_setClipboard(data, type?)` and `GM.setClipboard(data, type?)` accept strings up to 1 MiB of UTF-8. The default type is `text/plain`; `text`, `html` and `text/html` are also accepted. HTML is copied literally, without inserting or executing it. The legacy call returns void and logs failures; the modern call returns a promise that confirms the write. Clipboard images, reads and selection preservation are unsupported. A write already accepted by the browser cannot be undone by disabling a script.

`GM_notification({text, title?, image?, silent?, tag?, onclick?, ondone?})` and `GM.notification` return `{remove()}` immediately. The positional `(text, title?, image?, onclick?)` form also works. `remove()` resolves after removal, and `ondone` runs once after confirmed closure. Titles identify the source script. Text is limited to 4 KiB, titles to 256 bytes and tags to 128 bytes. Images must be inline base64 PNG/JPEG/GIF/WebP up to 32 KiB; remote images are rejected without fetching. A repeated tag replaces the same document instance's earlier notification. `silent` applies on Chrome/Edge; Firefox does not support that native option and ignores it. Zombie options, persistent notifications across worker restarts and cross-tab tag replacement are unsupported. Native permission denial or creation failures log an error; `remove()` then rejects. System notification settings may suppress a visible toast even when the browser accepts it.

`GM_download({url, name, ...options})` and `GM.download` also accept `(url, name)`. Options are `headers`, `timeout`, `anonymous`, `redirect`, `saveAs`, `conflictAction: 'uniquify'`, `context` and the existing HTTP callbacks (`onloadstart`, `onreadystatechange`, `onprogress`, `onload`, `onerror`, `onabort`, `ontimeout`, `onloadend`). The response uses a Blob. Completion means the native browser save finished; progress describes the initial HTTP transfer. A download uses GET with a 120-second HTTP timeout and 16 MiB response cap. The HTTP cookie/header/redirect rules below apply, including `@connect` checks at every hop; without `@connect`, any HTTP(S) destination is allowed. The grant permits network access without also requiring an HTTP grant.

`name` must be a single filename of at most 240 UTF-8 bytes, without directories, reserved device names or invalid filename characters. A collision creates a unique filename; overwrite mode, Blob/data URL inputs, streaming, POST bodies and files larger than 16 MiB are unsupported. Files save to the browser's download directory, or its chooser when `saveAs: true`; browser prompts and protections remain in force. Files are never opened automatically. Saved files remain on disk after a script is disabled.

There are at most four active desktop helpers per connection, eight per script and 32 overall, with 32 attempts per helper kind per script per minute. Editing, disabling, deleting, page unload, permission revocation or connection loss clears owned notifications and cancels unfinished downloads where the browser still grants access. Pending callbacks/promises settle without retries. After an abrupt worker termination, an already accepted native save may still finish and its result cannot be delivered to the old promise; inspect the browser's Downloads page before retrying. Stale userscript notifications are cleared on worker startup or when permission is restored. Helpers are not a full implementation of every [Violentmonkey option](https://violentmonkey.github.io/api/gm/).

### Element and tab helpers

Grant the exact spelling your script calls. `GM_addElement('div', {textContent: 'Hello'})` adds an element to the body, or the document root while the body is absent. Script/style/link/meta elements default to the head or document root. `GM.addElement(parent, 'span', {textContent: 'Hello'})` uses the supplied element, document fragment or shadow root. Attribute values must be strings; `textContent` sets text directly, and other entries use DOM attributes. Both spellings return the element immediately and support a one-use `.then(element => ...)`, as does `GM_addStyle`. At most 64 elements may await a missing document root. Page CSP and Trusted Types still apply; this helper does not provide Violentmonkey's CSP-bypass behavior.

`GM_openInTab('/next', {active: false})` resolves a relative URL against the current page and opens in its window. Both spellings return a control immediately, including `GM.openInTab`; they do not return promises. Options are `active` (default true), `insert` (default true) and `pinned` (default false). A boolean second argument means **open in background**, so `true` means `active: false`. Insertion places the tab next to its source and requests a native opener; `insert: false` leaves placement to the browser. URL credentials, non-HTTP(S) destinations, unknown options and Firefox `container` selection are rejected. Source windows are preserved, but inheriting Firefox cookie containers is not supported.

Use `handle.close()` to close only the tab created by that script instance, including immediately after requesting it. `handle.closed` updates after confirmed closure, and `handle.onclose = () => ...` receives one notification. Creation errors mark the handle closed and log a console error without invoking `onclose`; failed closes log an error and can be retried. There are at most 8 connected handles per instance, 16 per script and 64 overall; at most 4 openings per script and 8 overall may be pending. Each script can request 32 openings per minute. These limits bound the helper, not arbitrary page JavaScript.

Editing, disabling, deleting, page unload, permission revocation or native connection loss invalidates existing handles while leaving their tabs open. They are not reattached or replayed after reconnection; `closed` retains its last confirmed state and no close callback is fabricated. An opening already accepted by the browser can finish after revocation. Ad filtering still applies to helper destinations. Automatic blocked-popup cleanup requires an opener in the browser's initial creation event; an API-created tab may lack that initial evidence and need `handle.close()` instead.

### Preparing dependencies

Save a script with its absolute `@require URL` and `@resource name URL` declarations. While it is disabled, choose **Prepare dependencies**. Downloads require HTTPS, with HTTP allowed only on `localhost`, `127.0.0.1` or `[::1]` for development. URL credentials, relative URLs and redirects are rejected. Downloads omit cookies and referrers, have a 30-second total deadline, and run as data without executing code in the manager. A `#sha256=<64 hex characters>` fragment pins the exact bytes; the manager always records a SHA-256 digest. A digest without a trusted pin detects changes to the cache, but is not proof of publisher identity.

Use **Review contents** to inspect the readonly preview, URL, size and hash, then enable the script. `@require` must be valid UTF-8 JavaScript; HTML responses are rejected. Libraries run in declaration order before the main source in the same native script world. The wrapper is strict JavaScript; libraries relying on sloppy-mode globals or the page's JavaScript objects may still need adaptation. Resources retain their bytes and MIME type. Imports, saves, startup and page loads do not fetch dependencies; startup verifies cached hashes before registering enabled scripts. Preparation failure preserves the old cache. Changing declarations clears it; body-only edits preserve it and still disable the script. Editing, deleting, cancellation or turning off the module aborts pending preparation and rejects stale results. Up to four preparations may run concurrently, without holding the manager's control queue.

### Userscript HTTP requests

Grant `GM_xmlhttpRequest` or `GM.xmlHttpRequest` explicitly. The manager shows `@connect` destinations; `self` means the current page's hostname, a hostname includes its subdomains, and `*` permits all HTTP(S) destinations. Without `@connect`, the network grant permits any HTTP(S) destination. This is separate from page-matching scope. Only enable this grant for code you trust with page data and destination cookies.

Supported options: `url` (relative to the page or absolute HTTP(S)), `method` (GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS), `headers`, `data`, `timeout`, `anonymous`, `redirect`, `responseType`, `overrideMimeType`, `context`, `upload`, and `onloadstart`, `onreadystatechange`, `onprogress`, `onload`, `onerror`, `onabort`, `ontimeout`, `onloadend`. Data may be a string, URLSearchParams, Blob, ArrayBuffer, typed array or FormData. FormData preserves ordered duplicate fields, Unicode, file names and binary bytes; let the browser set its Content-Type and boundary. It supports at most 256 entries, with framing included in the upload allowance. Responses support text, JSON, arraybuffer, Blob and inert parsed documents. Response fields include status, statusText, finalUrl, responseHeaders, readyState and response; text responses also populate responseText, and document responses responseXML. `context` stays local. HTTP errors such as 404 still produce `onload`/a resolved promise; transport errors reject. Invalid JSON returns null. Callback errors are reported without skipping terminal cleanup.

Requests are limited to 8 MiB upload, 8 MiB response, 32 KiB headers and 30 seconds, even for timeout 0. There may be four active requests per script instance, eight per script or browser tab, and 32 overall. HTTP and downloads share a 64 MiB reservation allowance; a new transfer can be rejected until another finishes. This is not a hard RAM cap: encoding and browser buffers add overhead. Cookies follow browser policy by default; `anonymous: true` omits them and prevents response cookie storage. Cookie/Host/Origin/Referer/User-Agent and other browser-controlled headers, embedded URL credentials, streams, synchronous requests and unsupported options are rejected. Intermediate progress does not expose partial response bodies. Accepted requests are never retried after disconnect or worker restart, including POST requests. Disable/edit/delete, permission revocation, port loss and page unload cancel pending requests.

Redirects follow by default, up to five hops; `redirect: 'error'` rejects the first redirect. Every destination must satisfy `@connect`, credentials in URLs are rejected and HTTPS cannot downgrade to HTTP. A 301/302 changes POST to GET, a 303 changes non-HEAD requests to GET, and 307/308 preserve method and body. All caller-supplied headers are removed across origins; browser cookies follow the destination policy unless anonymous. Source installation and dependency preparation still reject redirects.

For actual upload progress, supply `upload: {onloadstart, onprogress, onload, onerror, onabort, ontimeout, onloadend}` with whichever callbacks you need. These describe sending the body; main callbacks describe the response. Progress frequency is browser-dependent, and a followed 307/308 can produce another upload cycle. Choose **Allow helper access** first: Chrome/Edge use an optional offscreen document for upload events, while Firefox needs optional `webRequestBlocking` to stop native redirects before checking their destinations. Firefox also needs that access to follow ordinary HTTP/download redirects. Requests fail closed when the required guard is unavailable. Plain FormData without upload callbacks uses the normal HTTP transport.

For example, this local script saves a setting and exposes a page command:

```javascript
// ==UserScript==
// @name Local page setting
// @namespace local.module-engine
// @match https://example.com/*
// @run-at document-body
// @grant GM_getValue
// @grant GM.setValue
// @grant GM_registerMenuCommand
// ==/UserScript==
let compact = GM_getValue('compact', false);
document.body.classList.toggle('compact', compact);
GM_registerMenuCommand('Toggle compact view', async () => {
  const next = !compact;
  await GM.setValue('compact', next);
  compact = next;
  document.body.classList.toggle('compact', compact);
}, { id: 'compact', autoClose: false });
```

The module boundary is explicit: `modules.js` registers bundled adapters; `background.js` keeps the existing verified blocker transaction and restricts management messages to extension pages; `userscripts-runtime.js` owns its scheduler, storage key and native registrations; `userscripts-core.js` parses metadata and compiles wrapper source without evaluating user code in the extension. Ad-filter settings are not migrated or duplicated. New privileged modules must ship as reviewed extension code.

Native registration, world configuration and persistent library writes are verified and rolled back on failure. Worker startup, browser startup and extension-update handlers restore saved intent. Script APIs use native `onUserScriptMessage` / `onUserScriptConnect` channels, a per-script capability, declared grants and browser-provided document/frame/URL information. No page-event bridge carries privileged requests. Capabilities rotate on edits and both enable and disable transitions; scripts cannot use these channels to change modules or protection settings. Connections are bounded to 256 overall and 64 per script or tab. The implementation follows the browser's [userScripts API](https://developer.chrome.com/docs/extensions/reference/api/userScripts) and Firefox's [optional-permission requirements](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/userScripts).

Manager operations have their own bounded capacity and run before waiting GM storage requests. One runner serializes all library writes, so a shutdown waits for the active transaction to finish before taking priority; it does not race or abandon an in-progress save. GM limits include active and waiting requests, apply across frames in the same native browser tab, and release capacity on success or failure. Queued requests recheck the current capability after management changes, so an old request cannot write after a successful disable or delete. A failed management change restores its prior state and reports the failure.

## Controls and scope

- The master switch pauses all static and custom network rules and cosmetic filtering.
- Individual switches select the ad, tracker, reported-threat and cosmetic layers. The old unverified malware toggle remains retired. Reported threats are a new layer, enabled by default when evidence is current; saved global pause and existing preferences are preserved.
- Reported-threat rules match only the listed hostname, including its root-dot spelling and ports. They do not infer subdomains or block shared hosting platforms. Explicit site exceptions still take precedence. This covers browser requests, not operating-system DNS or other applications.
- An expiry alarm, hourly guard and worker/startup checks disable the reported-threat layer when its evidence expires. Browser alarms may be delayed during sleep or suspension; disabling occurs when the browser dispatches the alarm or next reconciliation. The popup displays expiry or evidence errors. Missing/malformed policy or unavailable alarms keep this layer inactive; other filters remain usable. Expiry depends on the local clock, and updates require a new manual evidence review and rebuild.
- Site exceptions include subdomains. The popup names an inherited parent exception; **Resume on example.com** removes matching exceptions for that parent scope, including sibling subdomains that inherited it. Cosmetic filtering also respects the top page's exception inside frames from other origins. Reload the page after changing a site exception so frame-level network permissions are recalculated.
- Custom entries accept DNS hostnames, IPv4 addresses, localhost, or HTTP(S) URLs. Only the hostname is used; paths and ports do not limit a domain rule. International names are stored in punycode. A leading `www.` is folded into the parent domain, preserving the original extension behavior. IPv6, credentials and filter syntax are rejected.
- Settings updates are serialized. Success is shown only after the browser accepts the network rules and their readback matches. Failed changes return an error, attempt to restore the previous rules/settings, preserve the entered text and show a retry control.
- Invalid entries saved by an older version are retained in local storage under `quarantinedDomains`, displayed as inactive entries, and excluded from active rules. Add corrected hostnames through the popup.
- Cosmetic filtering hides matching page elements. It does not inspect downloaded files or determine whether a page is trustworthy.
- **Community lists** are a separate switch. The builder converts supported domain and URL-pattern blocks with their third-party, resource-type, site (`domain=`), `match-case`, `important` and pop-up options, their exceptions, generic and site-specific CSS, and the advanced operators documented below. Plain domain blocks with identical options are merged into domain-list rules. Unsupported filters, including network regexes and scriptlets, are skipped and counted in `rules/community-info.json`. List exceptions rank below reported threats, custom blocks and site pauses, and never apply to domains Module Engine's own ad, tracker or site-check lists block. Browser rules cannot tell a pop-up from a normal page load, so a list pop-up pattern that is not tied to one host applies only to page loads started by another site. The lists are not refreshed automatically.
- **Always Allowed Domains** (popup list, or the *Allow* button next to a blocked server in the activity log): requests to these domains and their subdomains are never blocked by the ad, tracker, site-check or community lists, on any site. Unlike *Pause on this site*, which turns filtering off on the pages of a site, this allows one server everywhere. Reported threats and your custom blocks still apply; the same domain cannot be in both Custom Blocked and Always Allowed. Entries accept a hostname or URL like custom blocks.
- **Block pop-ups and redirects** (popup switch, per site and its subdomains): a page-level script on the chosen site and each injectable child frame refuses windows opened by script, script-made clicks on links to another host scope, and clicks on disguised links to another host scope (invisible, or page-covering overlays). An exact host and its parent or child hosts share a scope; independent sibling hosts are kept separate so tenants on `github.io`, `pages.dev` and similar shared platforms cannot inherit each other's trust. Ordinary visible links still work. It does not depend on knowing the ad network's domains. Page-world block claims are deliberately not added to the activity log because a page could forge them. Reload after turning the switch off to remove an already-installed page hook; it is inactive on new pages while the site is paused or the master switch is off. Browser-restricted frames and pop-up routes that do not use these JavaScript hooks can still bypass this optional layer.

  On Chrome and Edge, the same switch also stops script-driven page replacements, including same-site URLs that could start a server redirect chain, scripted reloads, delayed redirects, script-submitted forms and meta refreshes. Stopping the first request keeps the current video document alive. Normal visible links, native forms, navigation within the same document, browser reload and Back/Forward remain usable. A synchronous script-handled link may navigate to its original exact destination. A real link or native form may follow server redirects normally; the guard does not know whether that chosen destination is wanted.

  Selected pages also receive a browser sandbox policy, inherited by embedded and nested frames, that prevents frames from navigating the top tab even after a genuine play click. Scripts, normal origins/storage, forms, presentation and other player capabilities remain allowed. Media and API response bodies are untouched. The policy is appended to the site's own CSP and cannot undo a stricter site policy. Locally generated video passed play, pause/resume, seeking and fullscreen checks in Chrome and Edge; player frames can still navigate and follow redirects within themselves.

  Compatibility is not universal: legitimate script-only full-page buttons, automatic next-page navigation and frame controls that intentionally navigate the top tab are also stopped. A blocked frame navigation can throw a browser security exception, so a player that performs that navigation before playback in the same handler may need this guard turned off. Pause protection or disable the guard and reload if a player depends on these behaviors. Already loaded pages retain their sandbox until reloaded. Responses generated entirely by a site's service worker may bypass the header policy; restricted injection, page-hook tampering and browsers without the Navigation API also limit protection. Live players, DRM playback and every redirect route have not been verified. The local tests never contacted a suspicious host.

- **Automatic cleanup of blocked pop-up tabs** works in Firefox and unpacked Chrome/Edge, independently of the per-site pop-up switch. It considers only a new tab with a browser-reported opener and its first HTTP(S) navigation. Chrome/Edge require a failed navigation and native feedback identifying a Module Engine block rule. Firefox requires a native aborted navigation plus confirmation from the actual enabled static, dynamic and session rules that a matching block outranks all possible exceptions or redirects; disabled static rules are excluded. Firefox checks domain and common URL patterns conservatively: regex, initiator/party constraints, unfamiliar conditions, or an exhausted matching budget cannot establish a block and may prevent cleanup. Ambiguous tabs stay open while browser network filtering continues. Existing or pinned tabs, tabs that already received page content, ordinary blank tabs without a confirmed block, and tabs without an opener are preserved. A blocked link opened in a new tab can also be closed because opener metadata does not distinguish it from a script-created pop-up. Pending navigation and rule changes cancel cleanup. The activity log records successful closes. Candidates expire after ten seconds, are capped at 64, and are not restored after a background restart. Firefox needs no debugging preference or new permission. Chrome/Edge installations without native match feedback keep the tab open.
- **Flag suspected ads** (popup switch, on by default): Module Engine watches requests that actually loaded (it never sees, and never flags, ones it blocked) and flags third-party servers that look like ads, for you to decide later. Signals: ad-like addresses (`/ads/`, banner, popunder, prebid, VAST), ad placement settings (`zoneid=`, placement, campaign), impression or click trackers, known ad-network script shapes, long random-looking script addresses, throwaway-looking domains (two words joined by a hyphen) loading scripts or frames, and on the page itself, frames in standard ad sizes from another site and elements labelled "Ad", "Sponsored" or 广告/廣告. Flags are grouped by exact server name in the *Flagged for review* table at the top of *My lists*, with the reasons, the page hosts they were seen on, a count and examples; **Block** adds that exact server to Custom Blocked Domains, **Allow** to Always Allowed Domains, **Ignore** stops flagging it, and *Clear all flags* empties the table. Nothing is blocked by a flag. Sibling hosts are conservatively treated as separate unless one is a parent of the other; this avoids merging unrelated shared-hosting tenants but may produce an extra harmless flag. Flags are kept in local storage (up to 500 servers, the oldest dropped first) until you decide or clear them; only page hosts, server names, reason codes and short paths without query strings are stored, and nothing is sent anywhere. Paused sites and always-allowed servers are not flagged; the master switch and the popup switch turn flagging off. Pattern matching misses ads served from the same host scope or ordinary-looking addresses and can flag harmless files, which is why it only flags.
- **My lists** (popup → *My lists*, or from the activity log): one page with tables for Always Allowed Domains, Custom Blocked Domains, Paused Sites and Pop-up and Redirect Blocking Sites, each with an add box and a remove button for every row, and a filter across all tables. Removing a row removes exactly that entry (the popup's *Resume* also removes a parent entry that covers the current site). A read-only table lists the hosts added from site checks, with the site each was found on and what it did.
- **Activity log** (popup → *Open activity log*): a page listing recent blocked requests (time, site, blocked server and path, layer) and extension events (settings changes, failures, installs/reloads, skipped YouTube video ads), with a per-server summary showing which sites each blocked server appeared on. It keeps up to 1,000 entries in session storage, so it is cleared when the browser closes; *Clear log* empties it and *Export JSON* saves a copy. Query strings are not recorded, and nothing is sent anywhere. Blocked-request entries come from the browser's rule-match feed, which Chrome and Edge provide while Module Engine is loaded unpacked. Firefox 159.0.1 does not provide it (even with `extensions.dnr.feedback` enabled), so in Firefox the log lists events only and says so. The YouTube player-data filter runs in the page and does not report to the log.
- On Fandom, cosmetic filtering also hides its ad wrappers after network blocking leaves them empty. This selector is restricted to Fandom hostnames and follows the existing cosmetic, site-pause and master settings.
- On YouTube (youtube.com, its subdomains and youtube-nocookie.com), the **ad layer** removes the ad schedule (`adPlacements`, `adSlots`, `playerAds`) from the player data before the player reads it, using the bundled `youtube.js` in the page's own script context. If a video ad still starts, the content script mutes it and jumps to its end, then restores the previous speed and sound. The **cosmetic layer** hides YouTube's feed, search, sidebar, masthead and in-player overlay ad slots; these selectors are restricted to YouTube hostnames. Pausing YouTube or turning off the ad layer unregisters the page filter for newly loaded YouTube pages; reload open YouTube tabs after changing it. In a YouTube embed on a paused site, the page filter still runs because it cannot see the parent page.

## Custom request filters

Open **My lists → Custom request filters → Edit network filters**. One line describes one request rule; blank lines and `!` comments are allowed. For example, these original fixtures use reserved `.test` addresses:

```text
||cdn.example.test/sponsor/*$script,third-party,domain=news.example.test
@@||cdn.example.test/sponsor/needed.js|$script,domain=news.example.test
```

The first rule blocks matching scripts initiated by the chosen site or its subdomains; the second allows that specific request. `domain=` refers to the frame initiating a request, which can differ from the top page. Full site pauses take precedence. Reported-threat rules and explicit domain blocks take precedence over these request exceptions. Always Allowed overrides a custom request block. Turning off cosmetic filtering or individual bundled lists does not disable custom request filters; the master switch does.

Supported patterns are `||host^`, `||host/path*`, and absolute HTTP(S)/WS(S) URLs anchored with `|`. A final `|` requires an exact URL ending. Hostnames are normalized without stripping `www`; internationalized hosts are encoded, and paths must already be URL-encoded. Supported resource options are `document`, `subdocument`, `stylesheet`, `script`, `image`, `font`, `object`, `xmlhttprequest`/`xhr`, `ping`, `media`, `websocket` and `other`, including `~` exclusions. `first-party`/`1p`, `third-party`/`3p`, their negations, `domain=site.test|~excluded.site.test`, and `match-case` are supported. Without resource options, a rule includes document navigation. `@@` allows matching requests, not an entire page.

The editor accepts at most 500 unique rules, 100,000 characters overall, 2,000 characters per rule, and 100 initiating-site entries per rule. These rules share the browser's dynamic-rule budget with domain lists. Regexes, scriptlets, redirects, parameter rewriting, remote includes, IPv6 hosts, bare global patterns and other unsupported options are rejected with a line number; the entire save remains unapplied. This is a bounded syntax subset, not a general uBO/EasyList importer.

Saved rules affect future requests; reload an affected page to revisit loaded resources. Saves use the existing transaction and browser readback. If another edit changed the stored text, the save is refused and the draft remains visible. **Discard draft** explicitly loads the current saved version, including deletions. Failed updates report errors and attempt to restore the previous configuration; a failed restore is surfaced as a protection error. Protection status is not inferred from a successful parse.

The **Reported-threat evidence** panel reads only bundled files. The builder validates the source catalog and generates `rules/threat-evidence.json` with hashes of the exact rule and policy bytes. The viewer also checks each host against its compiled exact-host rule and verifies the expiry calculation. These checks detect mismatched artifacts; they do not authenticate a security publisher or establish a host's current reputation. Observation dates retain their source precision, including month-only dates. Threat hosts are inert, defanged text; only the approved publisher reports have links, and none are fetched automatically. Search filters these entries too. Missing, expired or unverified evidence does not appear as current active protection.

## Cosmetic filtering

- **Generic Cosmetic Filters** is enabled by default and can be switched off in the popup or My lists → Page hiding. It uses the existing local snapshots; no lists were downloaded for this upgrade. Native CSS handles elements added after page load without a repeated JavaScript scan.
- **Sites with hiding disabled** restores hidden elements on a site and its embedded frames while ad, tracker, community and reported-threat network rules stay enabled. This is narrower than the existing full site pause. Entries cover their subdomains and can be removed individually in My lists.
- **Custom hiding rules** accepts one site-scoped CSS or supported advanced rule per line, for example `example.com##.sponsored-card`. Use `example.com#@#.sponsored-card` to exempt that exact selector, including matching bundled selectors. Multiple sites and exclusions are supported: `example.com,~shop.example.com##.sponsored-card`. Custom rules require at least one positive site; site names retain `www` and are normalized to ASCII for IDNs. Empty lines and `!` comments are allowed.
- The editor validates CSS in the current browser before saving, reports the failing line, preserves unsaved drafts, and refuses to overwrite a newer save from another window. Limits: 500 rules, 100,000 text characters and 1,000 characters per selector. Saving an empty list clears it. Open tabs react to saves, removals, switches and cosmetic pauses. Changes use the existing serialized settings transaction and rollback path.
- Generic and site selectors respect exact-selector exceptions and whole-host `generichide` / `elemhide` exceptions supported by the compiler. Excluded sites affect only the rule carrying that exclusion. `generichide` suppresses generic hiding; `elemhide` suppresses all cosmetic hiding on the matching frame, including custom rules. These exceptions never create network allow rules. Custom hiding otherwise remains available when Community lists is off.

- **Advanced Page Hiding** is enabled by default and has its own switch in the popup and My lists. Supported operators are case-sensitive literal `:has-text(text)` / `:-abp-contains(text)`, nested `:has(...)` / `:-abp-has(...)`, and `:upward(1)` through `:upward(10)` or `:upward(.container)` within ten ancestors. For example, `example.com##.label:has-text(Sponsored):upward(1)` hides the label's parent. Quoted text supports escaped quotes and backslashes; regex text is refused. `#?#` explicitly selects the advanced engine, with `#@?#` for exceptions. With `##`, native CSS `:has()` stays in CSS when it contains no advanced operator.
- Advanced blocking requires a positive site scope. Limits per rule: four nested levels and eight operators; literal text is limited to 200 characters. Sibling-relative queries, procedural selector lists, CSS suffixes after an advanced step and unsupported operators are refused. The compiler reports skipped entries instead of broadening them. Browser CSS validation checks every selector fragment before activation.
- The runtime restores a container when it stops matching or filtering is paused. It owns a random marker attribute and one style element, preserving inline styles. Mutation bursts share one pending scan. Each pass allows at most 64 active rules, 5,000 selected candidates, 20,000 operations, 1,048,576 UTF-16 text units and 32 ms measured between operations. Native selector calls are synchronous and cannot be preempted, so 32 ms is not a hard wall-clock ceiling. A limit stops advanced hiding for that frame and restores its changes; CSS and network filtering continue. The activity log records the reason. Edit the rules, toggle Advanced Page Hiding off/on, or reload the page to retry. Repeated unrelated setting changes do not retry a suspended rule set.

### Reddit app-promotion overlays

With **Page hiding** enabled, Module Engine recognizes English Reddit app prompts such as **Get the best of Reddit in the app** together with an app button inside a dialog or large fixed overlay. It hides the promotion and an associated decorative backdrop, closes native app modals, and releases their scrolling, pointer and main-content inertness locks. Late insertions and discovered open shadow roots are supported. Comments, inline discussions of the app, other websites, and separate login dialogs are preserved.

This uses the existing Page hiding switch, site hiding pause and full site pause; it does not require a userscript or new permission. Pausing restores the repair's changes while preserving newer page style edits. Reload the extension and Reddit tabs after installing this source update. In Edge, first load the repository at `edge://extensions` → **Developer mode** → **Load unpacked**.

The fix is verified against locally authored fixtures, not the live Reddit DOM in the screenshot. Different wording, closed shadow roots, unrelated overlays or page event handlers may need a separate targeted adjustment.

### Visual element picker

1. On an ordinary HTTP(S) page, open Module Engine and choose **Pick an element to hide**. Cosmetic filtering must be enabled for that site.
2. Point to an element and click, or use **Parent**, **Child**, **Previous**, **Next** and **Use element** with the keyboard. Selection does not activate the link underneath.
3. Review or edit the CSS selector and match count. **Preview** hides current matches temporarily; **Restore preview**, **Pick again**, **Cancel** or Escape restores them without overwriting inline styles.
4. Choose **Save hiding rule** to persist the rule. Edit or remove it later in **My lists → Custom hiding rules**. A failed save keeps the draft open and reports the error.

The picker prefers a unique ID or a short tag/class selector, then a structural path if necessary. It does not derive selectors from page text, links or form values. Generated paths are limited to 16 ancestor levels and 1,000 characters. The preview accepts plain CSS matching 1–100 current elements; it refuses document roots, its own controls and unsupported selectors. DOM changes refresh the preview; saving checks the current matches again. Saved CSS can match additional elements added later. Changing site layouts or generated class names can require adjusting a rule. Advanced operators remain available through the text editor.

The picker operates in the top document. It can select an iframe or shadow host as a whole, but cannot pick elements inside another frame or a shadow root. Its controls use a closed shadow root; the isolated extension context keeps the draft and last validated selector, accepts native user edits, and rechecks that state when saving. Page scripts cannot replace a saved selector by rewriting a control before a genuine Save click. It restores temporary changes when cancelled, replaced, paused, expired, removed from the page or unloaded by navigation. It does not make a page trustworthy or prevent the page from modifying its own DOM.

Opening the picker creates a capability valid for ten minutes, held only in session storage (at most 20 recent sessions). Saving is tied to the browser-provided tab, top frame, URL and document ID when available; the hostname comes from that tab, including `www`. The background rechecks pauses, existing exceptions and editor limits, and appends to the latest saved text so concurrent edits are preserved. A capability cannot save a second, different selector. The general settings-writing interface remains restricted to extension pages. [uBO's element-picker documentation](https://github.com/gorhill/uBlock/wiki/Element-picker) informed the feature choice; this selector generator, overlay and authorization flow are original code.

This upgrade does **not** establish full uBO parity or superiority. Unsupported procedural operators, arbitrary scriptlets, network regex filters, some path-specific cosmetic exceptions and other unsupported list options remain skipped and counted in `rules/community-info.json`. Custom request filters are edited in My lists; the picker saves cosmetic CSS only. There is no network-request picker, temporary zapper or automatic remote list updater. Streaming-ad and anti-blocker behavior varies by site; offline checks do not prove live YouTube/Twitch/Google coverage or anti-detection. [uBO's procedural filtering documentation](https://github.com/gorhill/uBlock/wiki/Procedural-cosmetic-filters) informed the earlier feature choice; the parser and runtime here are also original code.
