# Module Engine development

Run commands from the repository root. The extension uses bundled JavaScript, HTML and CSS without a package-install step. Node 22+ runs the JavaScript tests; PowerShell 7+ runs the offline list builder and rule tests.

Keep `manifest.json` at the repository root and load that same folder as the unpacked extension. Application JavaScript, HTML and CSS live under `src/`: `background/` coordinates extension lifecycle and modules, `blocking/` contains page/network protection, `userscripts/` owns parsing and execution, `appearance/` holds the website theme, `ui/` groups each page with its editor/assets, and `shared/` holds common contracts. Icons, rules and vendored assets remain in their existing top-level directories. Node helpers stay in `mcp/` and `development/`; tests and maintenance tools stay in `tests/` and `scripts/`. The project website is one self-contained page, `site/index.html`, outside the extension package; it uses system fonts and an embedded icon, so it makes no requests to other sites. The README's screenshots live in `docs/screenshots/`; retake them in Chrome when the pages they show change. No bundler or installation step is required.

Manifest entries, `runtime.getURL`, offscreen document URLs and injected-script file lists are extension-root relative. HTML navigation/assets and worker `importScripts` are relative to their page/worker. Keep that distinction when adding paths. `scripts/extension-files.cjs` supplies one runtime inventory to every browser package and hash list, excluding local Node helpers and transient files. `tests/extension-layout.test.cjs` checks the inventory and static manifest/HTML/worker/injection references; native suites cover dynamically selected resources. Historical verification records retain the old paths belonging to their tested snapshots.

The legacy `BlockAds` globals, storage keys, native userscript registration identifiers, test prefixes and Firefox extension ID are retained for compatibility; the displayed project name is **Module Engine**. The layout change does not migrate or reset saved settings, userscripts or GM values.

`src/blocking/overlays.js` owns reversible isolated-world prompt cleanup for `src/blocking/reddit.js` and `src/blocking/prompts.js`. `src/blocking/content.js` supplies one active policy list, so overlapping protections share scroll/inert ownership. Reddit's app-heading/action policy remains limited to Reddit and follows cosmetic settings. Notification reminders and install-to-play/download policies have independent booleans and `promptAllowedDomains`. The background derives top/frame exceptions from native sender URLs; content scripts cannot change them. No prompt content crosses extension messaging or enters logs.

`src/blocking/buttons.js` uses isolated-world window capture listeners registered synchronously at document start. `src/blocking/content.js` enables them only from verified background state (`deceptiveButtonBlocking`), sharing `promptAllowedDomains` with prompt controls. Listeners stay in place while disabled to preserve ordering on resume; pagehide disables the guard and removes its single notice/timer, pageshow refreshes state, and context loss or a reported error stops it. There is no per-click extension request, DOM observer or page-wide scan. Classification bounds the event path, label text, ad ancestors, nearby children and hit-test results. `src/shared/shared.js` supplies the existing conservative hostname comparison.

Strong signals are required: action plus ad placement, external link above an actual video in the hit stack, or Play plus an installer/script destination. Plain downloads, sibling links, articles, forms and same-site player overlays are negative fixtures. The guard cancels matching activation without replaying input or changing links. Touch events stop page handlers but retain native panning defaults; native touch-device behavior has not been verified. Context-menu navigation and handlers that already ran cannot be undone. See the native contracts for [event cancellation](https://developer.mozilla.org/en-US/docs/Web/API/Event/stopImmediatePropagation), [middle-click default handling](https://developer.mozilla.org/en-US/docs/Web/API/Element/auxclick_event) and [viewport hit testing](https://developer.mozilla.org/en-US/docs/Web/API/Document/elementsFromPoint).

The engine preserves content/form containers, closes native modals/popovers, and releases root scroll/pointer locks and inert main-content ancestors. Newer page style edits survive pausing; unrelated visible dialogs retain their locks. One debounced observer watches the document and discovered open shadow roots. Scans stop at 20,000 elements, 64 roots, 64 candidate anchors or 64 hidden elements. Classification bounds text at 4,000 characters/256 text nodes and 64 actions of 160 characters each. Text-node boundaries avoid joining adjacent block labels, and non-rendered script/style data is ignored. Removing a policy restores its owned changes before the remaining policies are evaluated. Closed roots, unfamiliar wording and scan-limit exhaustion are documented limits.

`src/blocking/notification-guard.js` is registered natively in MAIN at `document_start` for HTTP(S) top pages while enabled, excluding full site pauses and prompt exceptions. Top-only registration avoids imposing a frame's policy on a paused cross-origin parent. Same-origin iframe getters and trusted load/input hooks guard accessible child realms; cross-origin frames and workers are outside that hook. The native Notification permission getter is captured without changing the permission; new requests resolve `denied` with asynchronous legacy callbacks, already granted requests resolve `granted`, and ungranted page `PushManager.subscribe` calls reject before native code. Existing granted push calls retain the native receiver/options. These page hooks require reload after settings changes and are not a tamper-proof permission boundary. No new permissions or dependencies are required; GM notifications use their existing extension API.

API contracts: [Notification.requestPermission](https://developer.mozilla.org/en-US/docs/Web/API/Notification/requestPermission_static), [PushManager.subscribe](https://developer.mozilla.org/en-US/docs/Web/API/PushManager/subscribe), and [registered content scripts](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/scripting/RegisteredContentScript). The offline fixtures check both permission request paths without invoking unguarded subscription code or contacting a push service.

The offline Reddit browser fixtures use the production content scripts and settings. Only the policy factory's default hostname is aliased to `www.reddit.com` on the owned loopback `/reddit-fixture` route in the disposable package. Evidence records the original source hash and the modified fixture hash separately. No Reddit URL or asset is requested; non-loopback traffic is denied. The shared runtime inventory includes these helpers in every browser fixture. `node tests/browser-smoke.cjs chrome --prompts-only` and `--buttons-only` (also `edge` or `firefox`) run focused fixtures; the full blocker suite includes prompt, button and Reddit regressions. Button tests require fresh notice feedback for each trusted blocked gesture, observe native tab creation, play a local canvas video and save only an owned CSV to the disposable download directory. Firefox pointer targets avoid its browser-owned Picture-in-Picture control, which is outside page event cancellation.

## Tests and local files

### Same-tab section navigation

`src/ui/shared/navigation.js` lets each existing packaged page host the other sections in lazy, retained, same-origin frames. Only the six fixed section paths can be routed. Each document keeps its own state and native ports; no connection secrets move to storage or another context. Native MCP and Network sender URL checks are unchanged. ### Appearance

The setting is stored in `storage.local` under `appearance` as `{ mode, accent, websites, websiteExceptions }`; the default (System, `#c8f23a`, websites off, no sites) is stored as no value. `src/shared/appearance-settings.js` defines it once for extension pages, the popup and the website content script: validation, comparison, subdomain-inclusive exceptions and when websites are dark. Pages write it directly. It does not pass through the background's settings transactions, because no browser rules depend on it.

`src/ui/shared/theme.js` loads in the `<head>` of every packaged page, after its stylesheets and `appearance-settings.js`. It applies the theme (`data-theme="light"` or `"dark"` on `<html>`; absent for System) and a chosen accent (`data-accent` plus `--theme-*` custom properties). `src/ui/shared/ui.css` maps those onto its tokens. The light theme block appears twice, once for the explicit choice and once inside the `prefers-color-scheme` query, because CSS cannot share one block between the two. Theme-dependent colours belong in those token blocks, not in page stylesheets with their own media queries.

A `localStorage` copy of the theme and accent (`moduleEngineAppearance`) is applied synchronously before first paint, then replaced by the stored value; a change that arrives first wins over that older read. Firefox can clear extension `localStorage` with site data, so it is only a cache. The default lime keeps its hand-tuned values. For any other accent, `theme.js` keeps the chosen fill and shifts OKLCH lightness at a constant hue until text reaches 4.5:1 against the theme's surfaces and accent tints, and edges reach 1.9:1 against cards. On-accent text is whichever of a dark tint or white contrasts more, with black or white as the fallback.

`src/appearance/website-theme.js` is a separate manifest content script for HTTP(S) pages, all frames and `about:blank` children, at `document_start`. It is static rather than registered because the blocker's rule transaction owns every registered content script. It reads `appearance` straight from storage, without waking the background, and applies later changes live. While websites are off it adds nothing to a page. Otherwise it inserts one style element and sets `data-module-engine-dark="on"` or `"off"` on `<html>`.

- **Filter:** the root gets `invert(0.95) hue-rotate(180deg)`. Media gets `invert(1) hue-rotate(180deg)`, except media nested in other turned-back media and SVG images, which are treated as icons. A fixed, filtered `::before` layer covers the canvas, which Chrome leaves outside the root filter. Full screen removes every filter.
- **Engine differences:** measured in Chrome 157 and Firefox 160, Firefox's root filter also covers the top layer and backdrops, while Chrome's covers neither the top layer nor the page scrollbar. The script picks the matching rules by engine, and the browser test checks the rendered pixels.
- **Already-dark pages:** the script reads the page's own colours, which filters do not change in computed styles.
  - At each of five points it walks the elements painted there (`elementsFromPoint`, topmost first) to the first mostly opaque background. A point on media is not counted.
  - It looks through dimming layers: see-through (`opacity` included), `position: fixed` and covering at least 90% of the window, with a positive `z-index` on the layer or an ancestor. Cookie notices and dialog backdrops are like this; a fixed tint that is not raised counts as the page's own background.
  - The body's background (else the root's, else the canvas) is worth three points, so a dark banner across part of the first screen does not make a light page dark.
- **Rechecks:** every frame while the page loads, then on the next frame when a theme attribute (class or a common theme data attribute) changes on `<html>` or `<body>`. A theme attribute change below `<body>` is checked at most every 500 ms, and only when the changed element is as wide as the window and nearly as tall as the page, such as an app's root. Inline style changes are ignored, because many pages rewrite them while scrolling. It restores its style or attribute if a page removes them.
- **Exceptions** follow the tab's site. A same-origin frame reads it, Chrome supplies `location.ancestorOrigins`, and a cross-origin Firefox frame asks the background with `WEBSITE_THEME_TOP`, which answers from the sender's tab record.

Run `node --test tests/theme.test.cjs tests/website-theme.test.cjs`. These cover:

- the accent derivation across preset, edge and random colours;
- the token, light-block and accent-rule structure of `ui.css`;
- `<head>` loading and side-menu consistency on every page;
- cache and storage ordering and failures;
- every website-theme decision against an offline document.

Two browser modules run inside `node tests/browser-smoke.cjs <browser>`:

- `tests/appearance-browser.cjs` drives the real Appearance page. It checks explicit themes over emulated system schemes, accent tokens on every open page, reload, a same-tab section, the narrow layout and Reset.
- `tests/website-theme-browser.cjs` serves owned localhost pages and reads rendered screenshot pixels. It checks the page, image, cross-origin frame, dialog and backdrop; already-dark and later-dark pages; a cookie notice, a dialog whose backdrop wraps it, a dark banner and an app root that turns dark; and the popup and Appearance controls. Its test image is light, so an image left inverted would read dark. `--website-theme-only` runs just that part.

### YouTube filtering and registration

Protection registrations reconcile by ID: unchanged scripts stay registered, changed scripts use native `scripting.updateContentScripts`, and only removed/added IDs are unregistered/registered. Updates explicitly send `excludeMatches: []` to clear old pauses. The same reconciliation handles rollback after a partial browser write or settings-save failure, followed by native readback verification. API references: [Chromium scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting#method-updateContentScripts) and [Mozilla updateContentScripts](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/scripting/updateContentScripts).

`src/blocking/youtube.js` inspects own data properties without calling page getters, up to 512 queued objects, 4,096 properties and eight levels. Only recognizable player records or explicit `playerResponse` records lose the three known schedule fields. It preserves and cleans an existing initial response when possible without replacing page accessors/read-only globals. JSON.parse and Response.json retain native errors and reviver semantics. Same-origin `/youtubei/vN/player` and `/youtubei/vN/next` Response.text bodies up to 4 MiB can be parsed/filtered/re-serialized before a cached parser or reviver consumes them; unrelated, invalid, unchanged and oversized text is returned verbatim. This does not intercept every alternate transport, pre-captured reader, raw JSON.parse reviver observation, locked global assignment or server-stitched ad.

`src/blocking/youtube-fallback.js` is isolated from page globals and enabled only from verified ad-policy state. Media events and relevant DOM mutations trigger inspection, with no polling timer. At most 32 media elements have owned state; previously owned elements are revisited even when displaced from the discovery window. Native media setters fail independently, seeking requires a finite duration and a range reaching the end, and usable skip buttons take priority. Disable/trusted pagehide disconnect observers/listeners and restore owned sound/rate changes; trusted pageshow refreshes policy. A skip log requires both an attempted skip/seek and an observed end to the marked ad state, not just muting.

Run `node --test tests/youtube*.test.cjs tests/background.test.cjs`, then `node tests/browser-smoke.cjs edge --youtube-only` (substitute `chrome` or `firefox` for shared compatibility). These fixtures alias only owned loopback `/youtube-fixture` in a disposable package, retain original/modified hashes, generate silent PCM media with byte-range support, and deny external traffic. They check native early injection, fetch readers, media seeking, controls, pauses, restoration, history navigation and unrelated registration updates. The normal full blocker suites remain separate; no YouTube visit or third-party media is required.

### Network metadata capture

`src/background/network-log.js` registers passive `webRequest` observers separately from blocking/settings transactions. No blocking flag, headers or body options are requested, and no additional manifest permission is needed. Only the exact native `src/ui/network/network.html` sender can open `ME_NETWORK_LOG`. Commands use a closed schema and bounded queue; up to four Network pages can connect, with one capture owner. There is no content-script capture interface. MCP receives only a separate read capability, with no reference to the UI command dispatcher.

Capture is off by default. Only an explicit Start command enables it; disconnecting the owner, closing its scoped tab, expiry or storage failure stops it. A restarted background restores sanitized session entries lazily without resuming capture. Native request IDs correlate lifecycle events and redirect hops; missing starts retain partial coverage. Clear keeps bounded in-flight markers so known late replies do not reappear. Entries and correlation state are bounded at 2,000, with a 2 MiB serialized entry budget. Session writes are debounced and serialized; writes/reads cannot silently replace errors with an empty log. URLs are projected to origin/path before entering the log, and arbitrary error text is omitted. UI output is literal text, updates once per second only when data changes, and renders 100 rows per page.

Run the unit suite, then these native fixtures one browser at a time:

```powershell
node --test tests/*.test.cjs
node tests/userscripts-browser.cjs chrome --network-log-only
node tests/userscripts-browser.cjs edge --network-log-only
node tests/userscripts-firefox.cjs firefox --network-log-only
```

The native suite uses local GET/POST/redirect/error endpoints, controlled in-flight responses, a blocked localhost canary and an authored GM storage/HTTP script. It checks native events, authorization, export redaction, live/filter/paging controls, stop/clear/disconnect/tab lifecycle and themes/layout. No desktop helper permission is needed. `tests/network-log.test.cjs` additionally covers storage failures, asynchronous disconnects, restore, expiry and count/byte/connection limits. Run `tests/browser-smoke.cjs` for blocker/shared-navigation regressions.

Browser limitations are documented in the [Chrome webRequest API](https://developer.chrome.com/docs/extensions/reference/api/webRequest), [Firefox webRequest API](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest) and [session storage contract](https://developer.chrome.com/docs/extensions/reference/api/storage). Missing DNR events are not evidence of allowed traffic; the logger never infers blocker ownership from a generic failure.

`module_engine_get_network_log` uses its own `network` approval scope, unchecked in the MCP page. The shared closed schema is enforced at the client-facing server, page bridge and background. The reader lazily loads canonical sanitized entries but performs no writes, capture commands or expiry mutations. It reports current capture status without extending the timer. Latest matching entries are copied under a 100-entry / 128 KiB bound; cached UTF-8 entry sizes avoid repeated serialization. Existing port expiry and revocation suppress stale deliveries. The MCP contract version is 1.1.0; stdio remains the default and HTTP keeps its existing authentication rules.

### MCP

Source-review safety uses the Unicode [Bidi_Control characters](https://www.unicode.org/reports/tr9/#Directional_Formatting_Characters): U+061C, U+200E/F, U+202A–E and U+2066–9. The userscript core detects them without changing source. Lint supplies warning diagnostics with original UTF-16 offsets and line/column positions; syntax errors still reject MCP proposals. The shared review UI escapes every control, bounds the location list to 20, and keeps acknowledgment in memory for one review. Synthetic events cannot acknowledge it. `US_ENABLE` independently requires `acknowledgeBidi: true` for affected source after validating the saved revision; no acknowledgment is stored or accepted from an agent tool argument. MCP checks before saving an Apply & enable proposal, then forwards the page's decision to that same runtime gate. Undoing a disable of affected code requires a fresh enable review. Existing enabled scripts are not forcibly disabled on extension reload, and ordinary RTL text remains supported.

Regression coverage is in `tests/userscripts-bidi.test.cjs`, `tests/userscripts.test.cjs`, `tests/debug-changes.test.cjs`, `tests/mcp-changes-browser.cjs` and `tests/userscripts-install-browser.cjs`. The native `--install-only` and `--mcp-only` suites check escaped previews, trusted acknowledgment, cancel/update/reset paths, original stored bytes and a blocked local ad canary. They use the existing disposable-profile/deny-proxy harnesses without OS desktop helpers.

`mcp/server.cjs` defaults to stdio and owns the private browser bridge. `mcp/rpc.cjs` shares the lifecycle, tools and cancellation between stdio and the optional `mcp/http.cjs` Streamable HTTP endpoint. Both use only Node core. HTTP requires an environment bearer token, exact loopback Host, no Origin, and a separate expiring client session; the agent and browser endpoints never share tokens. DELETE/expiry invalidates browser approval, pending reads and pairing codes. Each request retains its session identity across asynchronous body reads and browser results. JSON responses need no SSE connection or result replay buffer.

`src/shared/debug-protocol.js` supplies the closed tool schemas shared with the browser. `src/ui/mcp/debug.js` requires a trusted form submission and holds connection secrets only in page memory; `src/background/debug-runtime.js` accepts one expiring port from the exact MCP page and repeats scope/tool checks. Background status uses read-only settings/native queries; `userscripts-runtime.js.inspect()` detects drift without registering scripts or writing storage. Never route MCP calls through the general settings message handler.

Change proposals (contract 1.2.0) add the `changes` scope and three tools. They are listed only when the server runs with `--allow-changes`; otherwise `rpc.cjs` treats them as unknown and `/pair` drops the scope. `debug-runtime.js` holds at most four pending proposals per session in memory and validates metadata, size, revision and identity with the userscript core. The MCP page first runs syntax checks in the editor's parser worker, so failing source goes back to the agent with diagnostics. Agent requests reach the background only as `read` port messages, which can create but never decide a proposal. Apply, Apply & enable, Reject and Revert are separate `decide` messages, sent only from trusted clicks on the page and refused without the scope. Decisions run one at a time, recheck the revision, and call the runtime's own `US_SAVE`, `US_ENABLE` and `US_DELETE`, so saving turns a script off and enabling still verifies dependencies. Each decision is logged with an `MCP:` prefix. `src/ui/shared/script-review.js` and `script-review.css` provide the access table that the manager's install review and the MCP page share. The port keeps its original `ME_DEBUG_READONLY` name for compatibility.

Captured userscript diagnostics reuse the existing authenticated native messaging path, with separate bounded admission, current capability/world/frame checks and approval identity checks before delivery. No messaging world is enabled solely for capture. Revocation clears captured errors and drops stale replies. Source and diagnostic text are untrusted and can contain private data; the agent must treat them as evidence, not instructions. See [MCP setup and limits](MCP.md).

Run `node --test tests/mcp.test.cjs tests/mcp-http.test.cjs tests/debug.test.cjs tests/debug-changes.test.cjs tests/userscripts.test.cjs tests/background.test.cjs`, followed by `node tests/userscripts-browser.cjs chrome --mcp-only` and substitute `edge`; Firefox uses `node tests/userscripts-firefox.cjs firefox --mcp-only`. Repeat each native run with `--mcp-http` to test HTTP. Native tests start the real process, connect with trusted input, verify reads/revocation and preserve a blocked local ad canary. `tests/mcp-changes-browser.cjs` then starts a separate `--allow-changes` process. It checks that syntax errors and script-dispatched clicks are refused, that Apply leaves the script off and it does not run, that Apply & enable runs the reviewed edit, and it covers Revert, Reject, activity entries, phone layout and disconnect. Evidence separately hashes the server source outside the disposable extension package. Tests use disposable profiles and the deny proxy; HTTP helpers receive only generated test tokens, then DELETE their session and are terminated by their owning fixture. Unit tests also exercise graceful server shutdown. No server/client installation or personal browser configuration is needed. Keep the Debug files in all disposable extension copy lists.

`src/blocking/popups.js` guards top-document replacements on the existing selected-site scopes. It uses trusted, cancellable Navigation API events; cross-origin URLs can be cancelled even when `canIntercept` is false. Script-only navigation is stopped before the first HTTP(S) request, including same-host URLs and script reloads, so an unseen server redirect cannot replace the video document. Ordinary native links/forms, exact link destinations captured before page handlers, same-document routing, browser reload and history traversal remain usable. Link intent expires with a zero-delay task so it does not authorize a later timer redirect. Transient user activation alone is insufficient: a play button can activate an ad redirect.

The [Navigation API specification](https://html.spec.whatwg.org/dev/nav-history-apis.html) explains why cross-origin frame-initiated top navigation is not covered by the event alone. `src/background/background.js` now appends a CSP sandbox to selected `main_frame` responses through one aggregate dynamic rule. Its restrictions are [inherited by descendant frames](https://html.spec.whatwg.org/multipage/browsers.html#sandboxing), including nested players, and omit both top-navigation permissions. The policy allows scripts, ordinary origins, forms, storage access, fullscreen-related player capabilities and other normal sandbox permissions. Priority 100 sits above request allows (4) and below site pauses (10000); paused request domains are explicitly excluded. The normal settings transaction verifies and rolls back both native policy and page-script registration. Header matches are neither logged as blocked requests nor treated as evidence for closing a tab. Existing CSP headers are appended to, never replaced; native tests verify stricter script/origin restrictions survive.

`sourceElement` arrived in [Chromium 135](https://developer.chrome.com/release-notes/135); older supported engines use the native `userInitiated` flag while retaining exact captured-link checks. The fixture removes this newer property to test fallback behavior with real navigation, not an old binary. A real link/form may legitimately follow a server redirect. Browser sandbox denials can interrupt a frame's current JavaScript handler; independent ad and player listeners are tested, but a player that requires a top navigation before playback cannot be guaranteed compatible. No new manifest permission or setting is needed. Enabling, pausing or disabling requires reloading the page because an already applied document sandbox is immutable.

The header policy applies only to responses that reach the browser network stack. [Service-worker-generated and CacheStorage responses can bypass DNR header changes](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest/#interactions-with-service-workers). Restricted injection, page-world tampering and deliberate native links to unwanted destinations also remain outside the guarantee. `tests/frame-redirects-browser.cjs` records a short WebM from canvas entirely inside the disposable browser and verifies decoding, playback controls, nested frames, iframe-local redirects and preserved server CSP. Keep tests on owned loopback pages behind a deny proxy; never use live suspicious destinations to demonstrate coverage.

See [verification and test commands](VERIFICATION.md#verification). Start with the offline tests. Browser tests use disposable profiles and owned loopback fixtures; live-site commands require separate opt-in.

Keep working logs, snapshots and scratch exports in `.artifacts/`, which is ignored. The build creates `rules/.build.lock` at runtime; it is not source. Packaged `rules/*.json`, list inputs and referenced verification records remain versioned. Existing dated verification evidence is deliberately retained even where new raw logs match ignore patterns.

## Source review and product direction

### Userscript execution compatibility

`src/userscripts/userscripts-core.js` owns execution flags and a shared binding prelude used by the compiler and inert Acorn diagnostics. Async wrappers preserve dependency order and report promise rejection; raw `@unwrap` compilation contains no API wrapper or capability token. Raw and wrapped scripts with native-exact scopes (`BlockAdsMatching.exact`) register unchanged. Other scopes get `BlockAdsMatching.rawGuard` as a separate script before the source. Wrapped source is plain text: a body such as `}); })(); code; (function(){ (function(){` closes the generated wrapper, so an in-wrapper `return` cannot keep it out of scope. The guarded code ends with `;let __moduleEngineScope_<hash>;`. Out of scope, the guard defines that name as a non-configurable global property, so ECMAScript global declaration instantiation throws a SyntaxError before any statement runs or any binding is created (spec `HasRestrictedGlobalProperty`). Do not replace this with a throwing prelude: function/var declarations are instantiated before a prelude statement runs. Page code can list the marker (`Object.getOwnPropertyNames(window)` includes it), so the hash covers `@name` and `@namespace`, as `sourceName` does. It never covers the install ID, which is unique to every user, or the source, which a local edit makes unique to one user. A site that knows a script's identity can pre-declare the marker to stop that raw script on its own pages; a source hash gave sites the same power over unmodified scripts. Isolated scripts and document-start page scripts run the guard in the same injection; later page-world scripts get a document-start guard registration (`-0`) so its error listener precedes page listeners. Page bridges register their code in USER_SCRIPT, so they guard in the same injection. A wrapped script guarded in the same injection omits its in-wrapper URL check, which would repeat the same decision; one with an early guard keeps it to recheck at run time. Chromium dispatches the error to that cancelable listener. Firefox reports isolated-sandbox errors straight to the console, so one redeclaration line can remain there.

`unsafeWindow` aliases the selected world's global, following the content/page distinction in the official [Violentmonkey metadata documentation](https://violentmonkey.github.io/api/metadata-block/). The default remains content. Wrapped `auto` is page-first with content fallback; page scripts can combine the real window with GM grants. Raw `auto` retains isolated native-global semantics. No Violentmonkey implementation was copied.

`src/userscripts/userscripts-page.js` contains the serialized MAIN bootstrap, page runtime adapter and isolated relay. Each bridged script gets an ordered MAIN bootstrap at document-start and a private USER_SCRIPT runner at its requested timing. The runner retains the native capability; only token-free code and JSON packets cross the DOM boundary. A synchronous claim precedes user code, so policy refusal permits fallback but runtime failures never cause a duplicate run. MAIN creates the executable inline script so Chromium applies the site's CSP. Cleanup removes child nodes without assigning a string to Trusted Types script sinks. There is no eval, policy relaxation or new permission. Load this module before the compiler in all package and test-copy lists.

The page is deliberately not an authentication boundary. A hostile site can observe or invoke its page script's granted APIs. The isolated host accepts only the fixed script's `US_VALUE` route and one fixed native port; the existing broker retains native sender/world/capability, grant, live-frame URL and permission checks. Packet, event-rate, in-flight and connection limits bound the relay; pagehide closes pending calls without retry, and persisted pages reconnect after pageshow. Native credentials never appear in MAIN registration code or its temporary source nodes. The bridge does not enable arbitrary extension commands.

Page-visible names must not contain the per-install script ID, because that value is identical on every site and would act as a cross-site identifier. Each runner registration ends with `//# sourceURL=blockads-userscript-<slug>.<hash>.user.js` from `sourceName` in `src/userscripts/userscripts-core.js`, and the bridge's inline page script reuses that name. In Chrome, Edge and Firefox, page code sees the name in `Error.stack` whenever a page-world userscript frame is on the stack, including callbacks, listeners and errors it catches. Chromium also puts it in `ErrorEvent.filename`. The slug keeps only the letters, marks, digits, `_` and `-` of `@name` (at most 64 code points, or `script` if none remain), so it cannot end the comment. The 64-bit hash covers `@name` and `@namespace`, not the source. All users of a script therefore share the name, edits keep it stable for DevTools breakpoints, and local changes to the source add nothing that identifies a user. Isolated scripts use the same name, keeping registrations independent of the world. The `--page-only` probe found no isolated frames in stacks read by page listeners in any of the three browsers. Names are deterministic, so `getScripts()` comparison stays stable; the first sync after this change re-registers once. Bootstrap and guard registrations carry no sourceURL. Diagnostics do not parse the name: MCP log entries take `scriptId` and `revision` from the authenticated message and pass the stack through unchanged.

The same rule covers page-world runtime data. Site code that runs while a bridged script executes can read the inline script's text through `document.currentScript` and the bootstrap's start event through `window.event`; the `--page-only` probe saw both in Chrome, Edge and Firefox. Site code that replaced `JSON` or `CustomEvent` before a document-end or idle script starts also sees every bridge packet. None of these carries the install ID or the capability. Native page scripts and the bridge's page configuration omit `id`, and the page runtime sends neither `id` nor `token`. The isolated host refuses page packets that name a script, then adds the install ID and capability itself, so the broker still authorizes by native sender, world and capability. The start event is `me-page-start-<hash>`, with the same identity hash as `sourceName`. In the page world, `GM_info.uuid` is `pageUUID`: an RFC 9562 version-8 UUID hashed from `@name` and `@namespace`. Every user of a script shares it, and it stays the same across sites, edits and reinstalls. Unlike Violentmonkey's value, it is not unique per installation. Content worlds, including the `auto` fallback, keep the install ID, because site code cannot read them. A script that copies `GM_info` into the page itself is outside this rule.

Schema-version-1 records gain optional `autoPageApproved`, normalized to false. Individual `US_ENABLE` opts auto scripts in; save/update clears it. Existing active auto scripts therefore remain isolated across extension and module restarts. The manager shows the migration note and site-trust warning, counts relay worlds toward Chromium's limit, and MCP distinguishes preferred execution from possible fallback. This field is not an authorization substitute for the native broker.

The page host and shared runner accept only trusted lifecycle events and require an actual suspended-to-restored transition. Startup is single-use, pauses while awaiting a DOM root, and resumes without replay. A generation counter invalidates queued work and late reads across navigation. Native calls not yet submitted are canceled; submitted storage/cookie writes retain their actual completion status. Across page-bridge suspension, completion replies contain only `ok`/`error`, never old value snapshots or cookies. Outstanding native operations remain counted until they settle. Closing the entire bridge still rejects its pending jobs with an uncertain-outcome message; no operation is retried.

The runner owns one current Port and handshake timer. It clears local ownership before calling native `disconnect()` because that call does not notify its own Port. Ready/disconnect/timeout callbacks verify current ownership; stale callbacks cannot stop a resumed connection. A common terminal stop path clears retry/handshake timers, body/element observers and helper handles on failure, revocation or retry exhaustion. Suspension invalidates optimistic storage patches while preserving native outcomes for operations already submitted. Modern storage-only scripts receive the same lifecycle guard without allocating an unnecessary Port. ### Broader userscript matching

`src/userscripts/userscripts-matching.js` owns metadata validation, native prefilters and the exact URL decision shared by `src/userscripts/userscripts-core.js`, the injected wrapper and the GM broker. Every wrapper checks scope, including `@grant none` and page-world scripts. Native matches/globs are conservative supersets; extended exclusions stay in the exact guard when a native exclusion would be too broad. Source records and library schema remain unchanged. `@connect`, timing, grants and ad filtering retain their existing contracts.

The regex parser accepts native non-Unicode syntax, including Annex B legacy forms. The native `RegExp` constructor validates the pattern first (parsing only, never matching), and a pre-scan counts groups so `\N` is a backreference only up to that count, as in browsers. No complete user regex is passed to JavaScript's backtracking engine; native regex predicates test one UTF-16 code unit only. Patterns without backreferences compile to a Thompson NFA. Each lookaround body is compiled separately and evaluated lazily as one linear pass over the URL that marks every position where it holds: lookahead bodies are reversed and scanned leftward, lookbehind bodies scanned rightward. Patterns with backreferences compile the same tree with capture, reset, empty-iteration and atomic-lookaround instructions into a bounded backtracking matcher that follows ECMAScript priority, case folding and backward lookbehind captures. It has a 65,536 choice-point cap. Compilation visits are capped separately, including repeated empty groups that produce no states. All evaluation shares one work budget per URL, exclusions run first, and all errors or exhausted budgets deny scope. Unit tests compare more than 200,000 short synthetic cases against native regex, plus over 1,000 generated patterns with lookarounds, backreferences, named groups and Annex B atoms. Inline `(?-i:)` modifiers are tested with explicit spec cases: Node's V8 reproduced spec-incorrect matches when such a group follows a capture and a duplicated alternative.

`.tld` uses the approved **Public Suffix List revision `905c2f8950fc646b8df073321ea567dadefaa3a2`**, including ICANN and private rules. `vendor/publicsuffix/public_suffix_list.dat` is plain UTF-8 domain data, not an archive or executable. Further work should start with understandable explanations of matched requests, reversible site fixes with an explicit expiry, and comparable measurements of breakage and resource use. `src/userscripts/userscripts-actions.js` implements clipboard, notification and download capabilities separately from blocker and manager scheduling. The wrapper serializes its validation/client functions into isolated worlds; the broker revalidates options after native sender, grant, capability and connection checks. Optional permissions are requested directly from the manager's trusted click. Native API listeners bind again when optional APIs become available. No helper exposes browser download IDs, clipboard reads, general download history or automatic file opening.

Clipboard writes are serialized; Chromium shares the bundled `src/userscripts/clipboard.html` offscreen document with active uploads. `src/userscripts/userscripts-offscreen.js` serializes acquisition/release and closes the document after its last lease ends, so a clipboard write cannot interrupt an upload. `src/userscripts/clipboard.js` accepts only the extension service worker and writes literal data using a copy event without parsing HTML. A temporary textarea in that private document supplies the native selection, including a sentinel for empty text; both field and listener are removed in `finally`. Firefox uses its existing background document. Notifications have connection-owned handles and clear stale `me-us-` objects on restart; Firefox's unsupported native `silent` field is omitted. Downloads reuse the bounded HTTP transport, then save buffered bytes with the native API; completion events and a post-creation lookup reconcile early saves. Chromium uses a data URL, while Firefox uses an owned Blob URL that is revoked on completion or cancellation. Pending native creations remain counted until they return after revocation, then are cleared/cancelled. An abruptly terminated worker cannot retract a native save already accepted by the browser; old jobs are never replayed.

The implementation consulted official [GM contracts](https://violentmonkey.github.io/api/gm/), [Chromium offscreen APIs](https://developer.chrome.com/docs/extensions/reference/api/offscreen) and [native downloads](https://developer.chrome.com/docs/extensions/reference/api/downloads). `tests/userscripts-desktop-browser.cjs` checks native `queryCommandEnabled('copy')` before intercepting `document.execCommand` in disposable copies: no actual OS clipboard content is read or changed. Source and fixture hashes are recorded separately. Notification creation/removal and harmless local files use real browser APIs; files stay in the run's temporary `exports` folder and are never opened. Chromium's helper permission dialog requires `--native-helper-prompt` and native acceptance; headless runs cannot answer it. `--desktop-only` focuses on these fixtures. Firefox's harness accepts only the matching native Module Engine helper prompt. No external test destination is used.

## Reviewed catalog and rule builds

The ad/tracker and unverified source of truth remains `lists/reviewed-domains.json`. Its review is explicitly **offline structure only**, not a current reputation check. Source hashes and prior rule scopes are recorded; reputation-verification and expiry fields remain unset. `lists/review-decisions.json` explains exclusions and categories. Six ad URL patterns are kept separately in `lists/browser-patterns.json`, and ad hosts recorded on named sites by `tests/site-ad-check.cjs` in `lists/site-ad-hosts.json`; both are browser-only and never exported. EasyList-format snapshots are recorded in `lists/community-lists.json` and converted into the separate community ruleset; they are never exported either. Dated browser threat evidence is a separate, manually reviewed input, `lists/reported-threats.json`; it is not exported to CyberAssist or merged into the version-1 catalog. See [the catalog contracts](../lists/README.md).

Use **PowerShell 7+ and Node 22+**, with Node available on PATH. The build is offline and treats domains as data; it never resolves them or visits their sites. The PowerShell compiler sends bounded UTF-8 data to `scripts/compile-procedural.cjs`, which uses the same parser as the extension. No packages or remote code are used.

**Community snapshot changes.** This upgrade uses only the existing local snapshots. If a replacement local snapshot is separately authorized, review its provenance and update its `downloadedAtUtc` and `sha256` in `lists/community-lists.json` before rebuilding. The builder refuses a list whose hash does not match its record. Reload the extension and refresh open pages after a build. There is no automatic list download.

```powershell
pwsh -NoProfile -File .\scripts\build-rules.ps1

# Optional: validate and build another catalog with the same closed schema.
pwsh -NoProfile -File .\scripts\build-rules.ps1 -CatalogPath C:\path\reviewed-domains.json
```

The builder validates bounded UTF-8/JSON input, duplicate fields/domains/IDs, DNS syntax, categories, source metadata and browser scope. Invalid input fails without replacing existing outputs. Exact host rules retain exact scope; domain-and-subdomain rules retain their documented wider scope. The shared CDN blanket rule and broad country-code TLD heuristics remain excluded.

`-FetchOnlineLists` and `-UrlhausCsvPath` now fail explicitly without downloading or replacing files. Unreviewed remote data is not automatically promoted into this catalog. No authenticated feed or malware samples are needed for this build.

Successful builds write `rules/ads.json`, `rules/trackers.json`, an empty compatibility `rules/malware.json`, the validated `rules/reviewed-domains.json` catalog, and the separate `rules/threats.json` / `rules/threat-policy.json` pair. Ad, tracker and reported-threat sets are declared as browser rulesets. The catalogs and policy are inert JSON metadata. The runtime reads the policy from the packaged extension, never from a remote server. Rebuilding an old evidence file does not renew its dates or expiry.

Every output is staged before replacement. A failed write triggers restoration of already replaced files; a lock prevents concurrent builds. Sudden power loss during multi-file publication is not an atomic transaction, so retain backups and rerun a successful build before reloading if publication is interrupted.
