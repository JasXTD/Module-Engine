# Module Engine development

Run commands from the repository root. The extension uses bundled JavaScript, HTML and CSS without a package-install step. Node 22+ runs the JavaScript tests; PowerShell 7+ runs the offline list builder and rule tests.

Keep the extension entry points at the root: the manifest and browser test packages refer to these paths. The legacy `BlockAds` globals, storage names, test prefixes and Firefox extension ID are retained for compatibility; the displayed project name is **Module Engine**.

`reddit.js` is a bundled isolated-world content helper, controlled by the existing cosmetic state in `content.js`. It is inert outside `reddit.com` and its subdomains. It recognizes an app-promotion heading plus an app button inside a dialog or large fixed overlay, preserves content containers, closes native app modals/popovers, and releases root scrolling/pointer locks and inert main-content ancestors. Changes are owned and reversible; newer page style edits survive pausing. Other visible dialogs keep their locks. A single debounced observer watches the document and discovered open shadow roots; scans stop at 20,000 elements, 64 roots, 16 matching app headings or 64 hidden elements. Closed roots and unknown wording are outside this repair's scope.

The offline Reddit browser fixtures use the production content scripts and settings. Only the factory's default hostname is aliased to `www.reddit.com` on the owned loopback `/reddit-fixture` route in the disposable package. Evidence records the original source hash and the modified fixture hash separately. No Reddit URL or asset is requested; non-loopback traffic is denied. Keep `reddit.js` in every browser package copy list when changing these helpers.

## Tests and local files

`popups.js` guards top-document replacements on the existing selected-site scopes. It uses trusted, cancellable Navigation API events; cross-origin URLs can be cancelled even when `canIntercept` is false. Script-only navigation is stopped before the first HTTP(S) request, including same-host URLs and script reloads, so an unseen server redirect cannot replace the video document. Ordinary native links/forms, exact link destinations captured before page handlers, same-document routing, browser reload and history traversal remain usable. Link intent expires with a zero-delay task so it does not authorize a later timer redirect. Transient user activation alone is insufficient: a play button can activate an ad redirect.

The [Navigation API specification](https://html.spec.whatwg.org/dev/nav-history-apis.html) explains why cross-origin frame-initiated top navigation is not covered by the event alone. `background.js` now appends a CSP sandbox to selected `main_frame` responses through one aggregate dynamic rule. Its restrictions are [inherited by descendant frames](https://html.spec.whatwg.org/multipage/browsers.html#sandboxing), including nested players, and omit both top-navigation permissions. The policy allows scripts, ordinary origins, forms, storage access, fullscreen-related player capabilities and other normal sandbox permissions. Priority 100 sits above request allows (4) and below site pauses (10000); paused request domains are explicitly excluded. The normal settings transaction verifies and rolls back both native policy and page-script registration. Header matches are neither logged as blocked requests nor treated as evidence for closing a tab. Existing CSP headers are appended to, never replaced; native tests verify stricter script/origin restrictions survive.

`sourceElement` arrived in [Chromium 135](https://developer.chrome.com/release-notes/135); older supported engines use the native `userInitiated` flag while retaining exact captured-link checks. The fixture removes this newer property to test fallback behavior with real navigation, not an old binary. A real link/form may legitimately follow a server redirect. Browser sandbox denials can interrupt a frame's current JavaScript handler; independent ad and player listeners are tested, but a player that requires a top navigation before playback cannot be guaranteed compatible. No new manifest permission or setting is needed. Enabling, pausing or disabling requires reloading the page because an already applied document sandbox is immutable.

The header policy applies only to responses that reach the browser network stack. [Service-worker-generated and CacheStorage responses can bypass DNR header changes](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest/#interactions-with-service-workers). Restricted injection, page-world tampering and deliberate native links to unwanted destinations also remain outside the guarantee. `tests/frame-redirects-browser.cjs` records a short WebM from canvas entirely inside the disposable browser and verifies decoding, playback controls, nested frames, iframe-local redirects and preserved server CSP. Keep tests on owned loopback pages behind a deny proxy; never use live suspicious destinations to demonstrate coverage.

See [verification and test commands](VERIFICATION.md#verification). Start with the offline tests. Browser tests use disposable profiles and owned loopback fixtures; live-site commands require separate opt-in.

Keep working logs, snapshots and scratch exports in `.artifacts/`, which is ignored. The build creates `rules/.build.lock` at runtime; it is not source. Packaged `rules/*.json`, list inputs and referenced verification records remain versioned. Existing dated verification evidence is deliberately retained even where new raw logs match ignore patterns.

## Source review and product direction

The 8 November 2026 userscript pass reviewed Violentmonkey's [GM API implementation](https://github.com/violentmonkey/violentmonkey/blob/master/src/injected/web/gm-api.js), [value-cache propagation](https://github.com/violentmonkey/violentmonkey/blob/master/src/injected/web/gm-values.js), [API documentation](https://violentmonkey.github.io/api/gm/) and [matching rules](https://violentmonkey.github.io/api/matching/). This was a targeted read of official source and documentation, without cloning, installing or executing Violentmonkey. Module Engine's implementation remains local JavaScript using native browser userscript APIs.

`userscripts-core.js` validates metadata, compiles URL guards and supplies the isolated-world API wrapper. Legacy reads and listeners hydrate a cache before source execution; scripts without those grants keep their native injection timing. Writes are ordered per document, with optimistic local notifications and confirmed remote snapshots. Revision checks prevent a late acknowledgement from replacing a newer remote value. `userscripts-runtime.js` verifies native sender, capability, grant, URL and frame before accepting operations, and rolls back failed persistent writes. Ports carry snapshots and menu invocations; they are removed on disconnect, revocation and out-of-scope top-frame navigation. All controls and writes remain serialized, with manager controls taking precedence over value traffic and bounded cache-connection startup.

Native `userScripts` matching combines match patterns **OR** include globs; ordinary content scripts combine them differently. This is explicit in [Chromium's matcher](https://github.com/chromium/chromium/blob/main/extensions/common/user_script.cc). Preserve native match scopes and prefilter includes with conservative globs, then enforce exact literal-query/fragment behavior in the wrapper and broker. Chrome requires at least one native match even for include-only scripts: a reserved `.invalid` placeholder satisfies that schema, and the exact guard grants it no extra scope. Do not replace native script worlds with a shared messaging-enabled world to bypass Chromium's 10-world document limit. Overflowing privileged scripts must stop before executing source, and the UI documents the limit.

The shared offline browser fixtures in `tests/userscripts-compatibility.cjs` cover native legacy/modern values, menu mouse and keyboard input, cross-tab listeners, timing, native URL prefilters, simultaneous cache/menu startup and Chromium overflow. Menu publication coalesces the latest state behind one in-flight request per native connection, with separate bounded admission; automatic startup cannot spend the ordinary GM value slots. `tests/userscripts-firefox.cjs` also exercises Firefox's actual optional-permission checkbox and Allow button in a disposable profile. The existing Chrome/Edge manager suite retains editing, import/export, shutdown pressure and worker restart checks. No test installs third-party scripts or visits blocked destinations.

The 9 November pass also reviewed official [metadata defaults](https://violentmonkey.github.io/api/metadata-block/), the [glob matcher](https://github.com/violentmonkey/violentmonkey/blob/master/src/background/utils/tester.js) and [GM request/resource APIs](https://violentmonkey.github.io/api/gm/). Defaults now use document-end, includes/excludes are case-insensitive, and GM_info exposes canonical grant metadata. Native case-sensitive glob prefilters deliberately accept a superset; near-matching paths can consume worlds before the exact guard rejects execution. This remains a documented native-world limitation, not a reason to share privileged worlds.

`userscripts-network.js` owns bounded fetch/stream handling and asset digest verification. The host authorizes GM requests through the same native capability and document binding as values, then releases its serialized queue before HTTP begins. Requests have per-connection/tab/script/global admission limits and AbortControllers tied to native connection lifetime. The isolated wrapper owns callbacks, promises, response decoding and resource Blob URLs. Initiating `port.disconnect()` does not fire that same port's disconnect listener; explicit revocation and pagehide must settle pending requests directly. Tests model both sides accurately.

`userscripts-editor.js` retains a native textarea for selection, undo and IME, with a text-node-only highlight layer and synchronized gutter. A revision-tagged worker debounces parsing, terminates stale work and falls back after two seconds without losing the draft. `userscripts-lint.js` parses the strict function wrapper without executing it, maps offsets to source lines and bounds token output. The bundled **Acorn 8.18.0** parser and MIT license are in `vendor/acorn`; its provenance records the approved local extraction from signed Node v24.22.1 and the user's clean Malwarebytes report. Defender was disabled, so no successful Defender scan is claimed. There is no package-install or remote parser loading step.

Schema-version-1 records accept optional local `tags`; older records normalize to an empty list. Metadata tags remain author-owned. Tag saves use revision checks without changing source capabilities; source-plus-tag saves are atomic and pause the script. Library array order defines start order. Registration IDs include an ordinal because native Chromium probes sorted by ID; stable world IDs preserve capability authorization. Registration changes replace owned registrations as one ordered batch, with rollback on failure, because Firefox probes retained earlier insertion order. This is verified behavior of the tested browser versions, not a guarantee of asynchronous completion order. `tests/userscripts-editor-browser.cjs` covers the UI, inert highlighting, diagnostics, tags, stale reordering and native phase order; `--editor-only` runs it in isolation.

HTTP bodies and responses are bounded at 8 MiB, downloads at 16 MiB, with a shared 64 MiB reservation allowance (not a hard process-memory ceiling). Ordered FormData entries cross the native message bridge as validated text/base64, then become a real browser FormData body. Avoid typed-array species operations in the serialized client encoder: Firefox's isolated-world file buffers reject cross-world constructor access. Redirects are manual, limited to five, recheck `@connect` before every destination, reject HTTPS downgrades and strip all caller headers across origins. Source/dependency downloads retain their separate redirect rejection and smaller limits.

`userscripts-xhr.js` supplies actual upload events in an extension DOM context. A private, random URL fragment identifies each broker request without reaching the HTTP server. Chrome/Edge session rule 950000001 removes Location for those extension-initiated XHRs; the response observer supplies the original destination. Firefox instead uses optional `webRequestBlocking` to capture and cancel a redirect before XHR follows it, because its DNR response changes precede that observer. Session rule 950000002 removes Cookie and Set-Cookie only for anonymous private upload URLs: `withCredentials=false` alone did not omit cookies in a native Edge regression. Guards are read back before use. These are scoped header/cancellation guards, never allow rules; ordinary ad filtering still applies. Plain requests use fetch with manual redirects. Upload permission removal, native port loss and script teardown abort owned work without replaying POSTs. See the official [DNR contract](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest) and [webRequest contract](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/webRequest); browser-specific behavior is also covered by owned native fixtures.

`tests/userscripts-transfer-browser.cjs` covers real multipart binary uploads, request/response progress, seeded anonymous cookies in both directions, guarded redirects, forbidden destinations never contacted, cancellation and exact 3 MiB browser saves. It runs inside the desktop-helper fixtures. `tests/userscripts-offscreen.test.cjs` covers shared helper leases, creation/permission failures, disconnects and cancellation. Package-copy lists include the editor worker, parser/license and both transport helper modules. No test downloads third-party code or opens saved fixtures.

Manual URL installation/update commands are extension-page-only. The optional `sourceURL` field lives in each schema-version-1 record; older records normalize to null. Source fetch admission and final revision checks use the manager queue, while bounded HTTP runs outside it. Cancellation, timeout, script revision changes and module pausing abort active checks. No unreviewed source is persisted. The manager retains the displayed bytes and expected script revision across worker suspension; `US_APPLY_SOURCE` revalidates identity, version and URL, preserves the latest values, and uses the existing transactional save/registration rollback. It never refetches approved bytes. This trusted manager route is not exposed to native userscript messaging. Metadata cannot redirect the saved update URL.

`tests/userscripts-install-browser.cjs` adds native source-review, cancellation, stale-editor, value-preservation, changed-dependency and worker-restart coverage using only locally authored loopback responses. It runs inside the existing userscript suites; `--install-only` focuses on this feature without requesting clipboard, notification or download access. Reference reading for this pass was limited to the official [metadata documentation](https://violentmonkey.github.io/api/metadata-block/), including its numeric version convention. No reference implementation was installed or executed.

The 11 November helper pass consulted the official [GM API contracts](https://violentmonkey.github.io/api/gm/), [tab implementation](https://github.com/violentmonkey/violentmonkey/blob/master/src/background/utils/tabs.js) and [API types](https://github.com/violentmonkey/types/blob/3fad29f648f3bcf3e821d853421672471043410e/index.d.ts). Both spellings of `addElement` and `openInTab` return synchronously. Element insertion stays in the native script world and respects CSP; missing-root observers are bounded and disconnected on teardown. Tab creation and closure use the existing native capability channel and release the scheduler before awaiting browser APIs. Ownership is keyed by connection plus an opaque handle, never by a script-supplied browser tab ID. Counts and a monotonic per-script rate window bound admission. Removal events and a post-creation lookup handle early closure; an uncertain lookup invalidates authority without falsely reporting closure. Revocation drops ownership, preserves existing tabs and never retries accepted openings. No manifest permission was added.

`tests/userscripts-helpers-browser.cjs` runs through the shared Chrome/Edge and Firefox suites. It checks real DOM nodes, shadow roots, style compatibility, synchronous tab controls, placement, pinning, close-before-open, external closure, revocation, exact grants and native blocking of a loopback destination. Chrome may deliver an API-created tab's first event without an opener even when a later lookup has one. Preserve conservative blocked-popup cleanup: its separate suite checks qualifying page-created popups, while helper tests also check explicit ownership-based closure. All runtime tests use local fixtures; the reviewed reference engine is not installed or executed.

Dependency preparation performs admission and final commit in the control queue, with fetch outside it. Results commit only against the original disabled script revision. Assets are stored inside the existing version-1 library record; absent assets normalize to null for older records. Hash checks happen before enabling/registration; startup never refreshes remote code. `tests/userscripts-network-fixtures.cjs` serves only locally authored data and code. `tests/userscripts-assets-network.cjs` exercises native caching, readonly review, binary resources, HTTP semantics and cancellation in all three browsers. All test-copy lists include the new transport module, including opt-in live harnesses which were not run for this work.

The 29 October 2026 review was limited to selected source files on uBO's `master` branch, read as text without cloning, downloading or executing its implementation. It was not a complete audit or a runtime comparison. The [review record](../verification/2026-10-29/network-filters/source-review.json) records the scope and sources.

- uBO already has filter-origin lookup and temporary exceptions in its [logger](https://github.com/gorhill/uBlock/blob/master/src/js/logger-ui.js), as well as background-change handling in its [filter editor](https://github.com/gorhill/uBlock/blob/master/src/js/1p-filters.js). These are existing capabilities to learn from, not missing features to claim as unique.
- The reviewed editor's merge routine assumes background changes have no deletions. That is a specific concurrency assumption to investigate; no uBO data-loss bug was reproduced. Module Engine instead requires the prior saved text to match before accepting a replacement and tests both concurrent additions and deletions.
- The reviewed [asset metadata](https://github.com/gorhill/uBlock/blob/master/src/js/assets.js) tracks list freshness, and the logger identifies contributing lists. Our dated, per-host threat-evidence panel is a useful direction for transparency. Reviewing these paths does not prove that comparable information is absent from every uBO component.
- Full uBO and uBOL have different browser architectures. The current [uBOL FAQ](https://github.com/uBlockOrigin/uBOL-home/wiki/Frequently-asked-questions-(FAQ)) includes custom filters and external subscriptions, so custom filtering is a parity step. This upgrade does not establish better coverage, performance or resistance to blocker detection.

Further work should start with understandable explanations of matched requests, reversible site fixes with an explicit expiry, and comparable measurements of breakage and resource use. Those are development priorities, not shipped features or proven advantages. Source inspection and isolated fixtures cannot establish universal blocking or live-site superiority.

`userscripts-actions.js` implements clipboard, notification and download capabilities separately from blocker and manager scheduling. The wrapper serializes its validation/client functions into isolated worlds; the broker revalidates options after native sender, grant, capability and connection checks. Optional permissions are requested directly from the manager's trusted click. Native API listeners bind again when optional APIs become available. No helper exposes browser download IDs, clipboard reads, general download history or automatic file opening.

Clipboard writes are serialized; Chromium shares the bundled `clipboard.html` offscreen document with active uploads. `userscripts-offscreen.js` serializes acquisition/release and closes the document after its last lease ends, so a clipboard write cannot interrupt an upload. `clipboard.js` accepts only the extension service worker and writes literal data using a copy event without parsing HTML. A temporary textarea in that private document supplies the native selection, including a sentinel for empty text; both field and listener are removed in `finally`. Firefox uses its existing background document. Notifications have connection-owned handles and clear stale `me-us-` objects on restart; Firefox's unsupported native `silent` field is omitted. Downloads reuse the bounded HTTP transport, then save buffered bytes with the native API; completion events and a post-creation lookup reconcile early saves. Chromium uses a data URL, while Firefox uses an owned Blob URL that is revoked on completion or cancellation. Pending native creations remain counted until they return after revocation, then are cleared/cancelled. An abruptly terminated worker cannot retract a native save already accepted by the browser; old jobs are never replayed.

The implementation consulted official [GM contracts](https://violentmonkey.github.io/api/gm/), [Chromium offscreen APIs](https://developer.chrome.com/docs/extensions/reference/api/offscreen) and [native downloads](https://developer.chrome.com/docs/extensions/reference/api/downloads). `tests/userscripts-desktop-browser.cjs` checks native `queryCommandEnabled('copy')` before intercepting `document.execCommand` in disposable copies: no actual OS clipboard content is read or changed. Source and fixture hashes are recorded separately. Notification creation/removal and harmless local files use real browser APIs; files stay in the run's temporary `exports` folder and are never opened. Chromium's helper permission dialog requires `--native-helper-prompt` and native acceptance; headless runs cannot answer it. `--desktop-only` focuses on these fixtures. Firefox's harness accepts only the matching native Module Engine helper prompt. No external test destination is used.

## Reviewed catalog and rule builds

The ad/tracker and unverified source of truth remains `lists/reviewed-domains.json`. Its review is explicitly **offline structure only**, not a current reputation check. Source hashes and prior rule scopes are recorded; reputation-verification and expiry fields remain unset. `lists/review-decisions.json` explains exclusions and categories. Six ad URL patterns are kept separately in `lists/browser-patterns.json`, and ad hosts recorded on named sites by `tests/site-ad-check.cjs` in `lists/site-ad-hosts.json`; both are browser-only and never exported. EasyList-format snapshots are recorded in `lists/community-lists.json` and converted into the separate community ruleset; they are never exported either. Dated browser threat evidence is a separate, manually reviewed input, `lists/reported-threats.json`; it is not exported to CyberAssist or merged into the version-1 catalog. See [the catalog contracts](../lists/README.md).

Use **PowerShell 7+ and Node 22+**, with Node available on PATH. The build is offline and treats domains as data; it never resolves them or visits their sites. The PowerShell compiler sends bounded UTF-8 data to `scripts/compile-procedural.cjs`, which uses the same parser as the extension. No packages or remote code are used.

**Community snapshot changes.** This upgrade uses only the existing local snapshots. If a replacement local snapshot is separately authorized, review its provenance and update its `downloadedAtUtc` and `sha256` in `lists/community-lists.json` before rebuilding. The builder refuses a list whose hash does not match its record. Reload the extension and refresh open pages after a build. There is no automatic list download.

```powershell
pwsh -NoProfile -File .\scripts\build-rules.ps1

# Optional: validate and build another catalog with the same closed schema.
pwsh -NoProfile -File .\scripts\build-rules.ps1 -CatalogPath C:\path\reviewed-domains.json
```

The builder validates bounded UTF-8/JSON input, duplicate fields/domains/IDs, DNS syntax, categories, source metadata and browser scope. Invalid input fails without replacing existing outputs. Exact host rules retain exact scope; domain-and-subdomain rules retain their documented wider scope. The shared CDN blanket rule and broad country-code TLD heuristics remain excluded.

`-FetchOnlineLists` and `-UrlhausCsvPath` now fail explicitly without downloading or replacing files. Unreviewed remote data is not automatically promoted into this catalog. No authenticated feed or malware samples are needed for this build.

Successful builds write `rules/ads.json`, `rules/trackers.json`, an empty compatibility `rules/malware.json`, the validated `rules/reviewed-domains.json` catalog, and the separate `rules/threats.json` / `rules/threat-policy.json` pair. Ad, tracker and reported-threat sets are declared as browser rulesets. The catalogs and policy are inert JSON metadata. The runtime reads the policy from the packaged extension, never from a remote server. Rebuilding an old evidence file does not renew its dates or expiry.

Every output is staged before replacement. A failed write triggers restoration of already replaced files; a lock prevents concurrent builds. Sudden power loss during multi-file publication is not an atomic transaction, so retain backups and rerun a successful build before reloading if publication is interrupted.
